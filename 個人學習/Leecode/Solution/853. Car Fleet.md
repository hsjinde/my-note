## 題目描述 (中文摘要)
一條單線道上有 `n` 台車開往終點 `target`。第 `i` 台車的起點是 `position[i]`、速度是 `speed[i]`（英里／小時）。車子**不能超車**：後車追上前車後，就只能貼著前車、以前車的速度一起開。

「車隊 (Car Fleet)」是位置相同、速度相同的一群車，單獨一台車也算一個車隊。若後車剛好在終點才追上前車，仍算同一個車隊。請回傳最終抵達終點的車隊數量。

限制：`1 <= n <= 10^5`，`0 < target <= 10^6`，`0 <= position[i] < target`，`position` 內的值**互不相同**，`0 < speed[i] <= 10^6`。

範例：
```
輸入：target = 12, position = [10,8,0,5,3], speed = [2,4,1,1,3]
輸出：3
說明：10 與 8 在終點會合；5 與 3 在位置 6 會合；0 自己一隊

輸入：target = 10, position = [3], speed = [3]
輸出：1

輸入：target = 100, position = [0,2,4], speed = [4,2,1]
輸出：1
說明：0 與 2 在位置 4 追上車子 4，三台一起以速度 1 抵達
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
不用模擬車子怎麼移動，只要比較「每台車在沒有阻擋時抵達終點要花多久」：離終點較遠的車，若單獨開也不會比前面的車隊晚到，就一定會在終點前（或剛好在終點）追上並併入那個車隊。
1. **演算法選擇**：採用 **排序 (Sorting) + 單調堆疊 (Monotonic Stack)**，堆疊中每個元素代表一個車隊的抵達時間。
2. **具體步驟**：
   - 把 `(position, speed)` 配對後，依位置**由近終點到遠終點**（位置大到小）排序。
   - 依序計算每台車單獨開到終點的時間 `time = (target - position) / speed`。
   - 若 `time` **嚴格大於**堆疊頂端（前方最近車隊的抵達時間），代表追不上，自成新車隊並推入堆疊。
   - 否則它會併入前方車隊，車隊的抵達時間仍由前方較慢的那台決定，堆疊不變。
   - 最後堆疊長度就是車隊數。

### English Interview Plan
Count how many groups of cars arrive at the target together, given that cars cannot pass each other.
1. **Strategy**: Sort cars by position in descending order and compare their unobstructed arrival times. Sorting costs $O(N \log N)$ and a single linear scan does the rest — no time-step simulation is needed.
2. **Execution**:
   - **Initialization**: Pair up `position` and `speed`, sort by position descending, and start with an empty stack of fleet arrival times.
   - **Iterative Step**: For each car, compute `time = (target - p) / s`. If the stack is empty or `time > stack[-1]`, push it as a new fleet; otherwise the car catches the fleet ahead and merges into it.
   - **Key Insight**: A car that would reach the target no later than the fleet directly ahead must catch it at or before the target, so the fleet's arrival time stays the slower (larger) one. The stack therefore stays strictly increasing from bottom to top.

## 演算法詳解

直覺做法是按時間一步一步模擬每台車的位置，處理追撞與合併。但抵達時間可能是分數、時間步長很難抓，而且每一步都要掃過所有車，最壞會到 $O(N \cdot T)$，既不精確也不夠快。

關鍵在於：**車隊的抵達時間只由隊伍中最前面那台車決定**。一台車只會被它正前方的車隊擋住，所以從最靠近終點的車開始往後處理，每台車只需要和「前方最近的車隊」比較一次：

- 自己的 `time <= 前方車隊的 time`：單獨開會比前車早到或同時到，但不能超車，所以一定會在終點前（或剛好在終點）追上並併入，到達時間變成前方車隊的時間。
- 自己的 `time > 前方車隊的 time`：即使沒有任何阻擋也比前車晚到，永遠追不上，自成一隊，並成為後面車子的新「前方車隊」。

因為只有更慢的車隊才會被推入，堆疊由底到頂嚴格遞增；這個寫法甚至不需要 pop，只要在要推入時比較堆疊頂端即可。

### 狀態變化 (State Transitions)
以 `target = 12, position = [10,8,0,5,3], speed = [2,4,1,1,3]` 為例，先依位置由大到小排序並算出各自的抵達時間：

| 位置 | 速度 | `time = (12 - p) / s` |
|---|---|---|
| 10 | 2 | 1.0 |
| 8 | 4 | 1.0 |
| 5 | 1 | 7.0 |
| 3 | 3 | 3.0 |
| 0 | 1 | 12.0 |

依序掃描：

| 處理的車 | time | 和堆疊頂端比較 | 動作 | 堆疊 |
|---|---|---|---|---|
| p=10 | 1.0 | 堆疊為空 | 推入，新車隊 | `[1.0]` |
| p=8 | 1.0 | `1.0 > 1.0` 不成立 | 剛好在終點追上，併入 | `[1.0]` |
| p=5 | 7.0 | `7.0 > 1.0` | 追不上，推入 | `[1.0, 7.0]` |
| p=3 | 3.0 | `3.0 > 7.0` 不成立 | 在途中追上 p=5，併入 | `[1.0, 7.0]` |
| p=0 | 12.0 | `12.0 > 7.0` | 追不上，推入 | `[1.0, 7.0, 12.0]` |

最終堆疊長度為 3，答案是 3。

注意 p=3 那台：它單獨開只要 3 小時，卻被 p=5（7 小時）擋住，實際抵達時間變成 7。所以後面的 p=0 必須拿 7.0 而不是 3.0 來比較——堆疊頂端存的是**車隊**的時間，而非正前方那台車原本的時間。

## 程式碼實作

```python
class Solution:
    def carFleet(self, target: int, position: List[int], speed: List[int]) -> int:
        # 由近終點往遠處理：每台車只會被正前方的車隊擋住
        cars = sorted(zip(position, speed), reverse=True)
        # 每個元素是一個車隊的抵達時間，由底到頂嚴格遞增
        stack = []

        for p, s in cars:
            # 用真除法：抵達時間可能是小數，// 會把不同時間截成同一個
            time = (target - p) / s
            # 嚴格大於才自成一隊；相等代表剛好在終點追上，題目規定算同一隊
            if not stack or time > stack[-1]:
                stack.append(time)
            # 否則併入前方車隊，車隊時間仍是前方較慢的那個，堆疊不必更新

        return len(stack)
```

## 正確性說明

1. **不重複 (No Redundancy)**：每台車只被處理一次，且只會產生兩種結果之一——推入成為新車隊，或併入前方車隊。被併入的車不會進入堆疊，因此不會被重複計數。
2. **不遺漏 (Completeness)**：
   - **各車隊的領頭車都以原速行駛**：用歸納法，最靠近終點的車沒有人擋；假設前面每個車隊的領頭車都以原速行駛，那麼新推入的車 `time` 嚴格大於前方車隊，也就是它在原速下比前方車隊晚到。兩台等速前進的車在「位置—時間」圖上是兩條直線，最多相交一次；若它在終點前追上前方車隊，交會後它的速度較快、單獨開會比前方早到終點，與 `time` 較大矛盾。所以它永遠追不上，也以原速行駛。
   - **併入的判斷正確**：若某台車 `time <= stack[-1]`，它原速開會不晚於前方車隊抵達，但它起點在後方又不能超車，只能在終點前或剛好在終點追上前方車隊，屬於同一隊。
   - 因此每個車隊恰好對應堆疊中的一個元素，堆疊長度就是答案。
3. **邊界條件**：
   - 單一車 `n = 1`：推入一次，回傳 1。
   - 所有車同時抵達（例如 `target = 10, position = [0,5], speed = [2,1]`，兩車時間都是 5）：第二台 `5 > 5` 不成立而併入，回傳 1，符合「剛好在終點追上也算同隊」。
   - 越靠後的車越慢（排序後時間嚴格遞增）：沒有人追得上，每台車各自一隊，堆疊長到 $N$。
   - 距離終點很近、速度很慢的車：`time` 可能是很小的小數，必須用浮點數或分數比較。

---

## 複雜度分析

- **Time Complexity**: $O(N \log N)$
  - 其中 $N$ 為車子數量（`position` 的長度）。排序花 $O(N \log N)$，之後線性掃描一次 $O(N)$，每台車只做一次除法與一次比較。排序的成本與輸入無關，因此最好與最壞情況都是 $O(N \log N)$。
- **Space Complexity**: $O(N)$
  - 配對並排序後的 `cars` 需要 $O(N)$。
  - 堆疊的大小等於車隊數：最好情況是所有車都併成一隊，只有 1 個元素；最壞情況是每台車各自一隊，$O(N)$。

## 常見誤區

1. **排序方向反了或沒有排序**：必須從**最靠近終點**的車開始處理。若由遠到近掃描，處理某台車時還不知道前面有誰會擋住它，無法判斷它屬於哪一隊。原始輸入的 `position` 也不保證有序。
2. **拿正前方那台車的原始時間比較，而不是車隊時間**：例如 `target = 10, position = [5,4,1], speed = [1,3,3]`，時間依序為 5、2、3。位置 4 那台被位置 5 擋住，實際要 5 小時才到；位置 1 那台若拿 3 和 2 比較會誤判成新車隊，得到 2，正確答案是 1（3 <= 5，併入）。這也是為什麼被併入的車不能推入堆疊。
3. **把推入條件寫成 `>=`**：題目規定剛好在終點追上也算同一隊。`target = 10, position = [0,5], speed = [2,1]` 兩台時間都是 5，用 `>=` 會得到 2，正確答案是 1。
4. **用整數除法 `//` 計算時間**：`target = 10, position = [4,3], speed = [2,2]` 的時間分別是 3 與 3.5，應為 2 隊；用 `//` 會變成 3 與 3，誤判成 1 隊。
5. **比較速度而不是時間**：後車比較快不代表追得上，還要看它離前車多遠、前車離終點多近。只有「抵達時間」同時考慮了距離與速度。

## 延伸思考

### 不用堆疊：只記前方車隊的時間
堆疊在這個寫法裡從來不會 pop，真正用到的只有頂端值，所以可以用一個變數取代整個堆疊，額外空間（不計排序）降為 $O(1)$：

```python
class Solution:
    def carFleet(self, target: int, position: List[int], speed: List[int]) -> int:
        fleets = 0
        slowest = 0.0
        for p, s in sorted(zip(position, speed), reverse=True):
            time = (target - p) / s
            if time > slowest:
                fleets += 1
                slowest = time
        return fleets
```

NeetCode 的寫法則是「先推入，再檢查新頂端是否 `<=` 下面那個，是的話就 pop」，結果相同，只是多了推入再彈出的步驟。堆疊版的好處是概念上與 [[739. Daily Temperatures]] 等單調堆疊題一致，也方便在面試中延伸成需要保留多個車隊資訊的變形。

### 避免浮點數：交叉相乘
要比較 $\frac{d_1}{s_1}$ 與 $\frac{d_2}{s_2}$（$d$ 為離終點距離），可以改比 $d_1 \cdot s_2$ 與 $d_2 \cdot s_1$，全程整數運算、完全沒有精度疑慮。本題的數值範圍在 $10^6$ 以內，IEEE 754 雙精度除法是正確捨入，相同分數會得到相同結果、不同分數也不會被捨入成同一個值，所以直接用 `/` 是安全的；但在數值範圍更大的變形中，交叉相乘是更穩健的做法。

### 利用位置值域：桶排序
因為 `0 <= position[i] < target <= 10^6` 且位置互不相同，可以開一個長度為 `target` 的陣列，以位置當 index 存放抵達時間，再由 `target - 1` 往 0 掃描，時間變成 $O(N + \text{target})$。當 $N$ 接近 $10^5$、`target` 不大時可以省掉排序的 $\log N$，但空間與 `target` 成正比。

## 小結

這題屬於「排序後線性掃描，用堆疊維護群組邊界」的題型：把物理模擬轉換成抵達時間的比較，就變成單調堆疊問題。

**核心觀念：**
- 不能超車的情境下，群組的行為由最前面（最慢）的成員決定，所以要從最靠近終點的一端開始處理。
- 比較「抵達時間」而非速度或位置，才能同時考慮距離與速度。
- 被併入的元素不要推入堆疊，堆疊頂端永遠代表「前方最近群組」的狀態。
