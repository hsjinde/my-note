## 題目描述 (中文摘要)
給定整數陣列 `temperatures`，`temperatures[i]` 是第 `i` 天的氣溫。請回傳陣列 `answer`，其中 `answer[i]` 是第 `i` 天之後**要再等幾天**才會遇到比當天**更高**的氣溫；如果之後都沒有更暖的日子，`answer[i] = 0`。

限制：`1 <= temperatures.length <= 10^5`，`30 <= temperatures[i] <= 100`。

範例：
```
輸入：temperatures = [73,74,75,71,69,72,76,73]
輸出：[1,1,4,2,1,1,0,0]

輸入：temperatures = [30,40,50,60]
輸出：[1,1,1,0]

輸入：temperatures = [30,60,90]
輸出：[1,1,0]
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
這題本質是「替每個元素找右邊第一個比它大的元素 (Next Greater Element)」，答案就是兩者的 index 差。
1. **演算法選擇**：採用 **單調堆疊 (Monotonic Stack)**，堆疊內維持「由底到頂溫度遞減」的 index。
2. **具體步驟**：
   - 由左往右掃描，堆疊裡放的是「還沒找到更暖日子」的那些天（存 index）。
   - 遇到新的一天 `i`，只要它比堆疊頂那天**嚴格更暖**，就把頂端 `j` 彈出，並填上 `answer[j] = i - j`。
   - 彈完之後把 `i` 推進堆疊，等待未來更暖的日子來結算它。
   - `answer` 預設為 0，掃描結束時仍留在堆疊裡的天數自然就是 0，不必另外處理。

### English Interview Plan
For each day, find the distance to the next strictly warmer day — a classic "next greater element" problem.
1. **Strategy**: Use a monotonic decreasing stack of indices. Each index is pushed once and popped at most once, giving $O(N)$ amortized time instead of the $O(N^2)$ brute force.
2. **Execution**:
   - **Initialization**: `answer = [0] * n`, so days that never see a warmer temperature need no extra handling.
   - **Iterative Step**: For each index `i`, while the stack is non-empty and `temperatures[i] > temperatures[stack[-1]]`, pop `j` and set `answer[j] = i - j`. Then push `i`.
   - **Key Insight**: The stack only holds days still "waiting" for a warmer day, and they are in decreasing temperature order — so a new day resolves them from the top down, and stops as soon as it meets one that is at least as warm.

## 演算法詳解

暴力解是對每一天往右掃到第一個更暖的日子，最壞情況（例如整段遞減）每天都要掃到底，時間為 $O(N^2)$，在 $N = 10^5$ 時會超時。

暴力解浪費在「同一段區間被重複掃描」。單調堆疊的做法是反過來想：不是每一天主動往右找答案，而是讓**新的一天回頭結算**所有比它冷、還在等待的日子。

為什麼堆疊會是遞減的？因為任何比新一天冷的舊日子都已經在推入前被彈出結算了，所以留下來的必定 $\geq$ 新一天的溫度。這個遞減性保證了：新一天從頂端往下彈，一旦遇到不比它冷的那天就可以停，下面的不必再看。

### 狀態變化 (State Transitions)
以 `temperatures = [73,74,75,71,69,72,76,73]` 為例（堆疊存 index，括號內為溫度）：

| i | 溫度 | 彈出並結算 | 彈完後推入 i 的堆疊 |
|---|---|---|---|
| 0 | 73 | — | `[0(73)]` |
| 1 | 74 | `0`：`answer[0] = 1 - 0 = 1` | `[1(74)]` |
| 2 | 75 | `1`：`answer[1] = 2 - 1 = 1` | `[2(75)]` |
| 3 | 71 | —（71 < 75） | `[2(75), 3(71)]` |
| 4 | 69 | —（69 < 71） | `[2(75), 3(71), 4(69)]` |
| 5 | 72 | `4`：`answer[4] = 1`；`3`：`answer[3] = 2`；遇到 75 停 | `[2(75), 5(72)]` |
| 6 | 76 | `5`：`answer[5] = 1`；`2`：`answer[2] = 4` | `[6(76)]` |
| 7 | 73 | —（73 < 76） | `[6(76), 7(73)]` |

掃描結束時 index 6、7 還在堆疊裡，代表之後沒有更暖的日子，維持預設值 0。

最終 `answer = [1,1,4,2,1,1,0,0]`。

注意 `i = 2` 的 75 度：它一直等到 `i = 6` 才被結算，中間 71、69、72 都沒能把它彈出，這正是 `answer[2] = 4` 的來源。

## 程式碼實作

```python
class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        # 預設 0：到最後都沒被彈出的天，本來就該是 0，省掉收尾迴圈
        answer = [0] * n
        # 存 index 而非溫度：天數差要靠 index 才算得出來，溫度則可隨時查回
        stack = []

        for i, t in enumerate(temperatures):
            # 必須是嚴格大於：同溫不算「更暖」，不能拿來結算
            while stack and t > temperatures[stack[-1]]:
                j = stack.pop()
                answer[j] = i - j
            stack.append(i)

        return answer
```

## 正確性說明

1. **不重複 (No Redundancy)**：每個 index 恰好被推入一次；一旦被彈出就已填好答案、不再回到堆疊，因此每個 `answer[j]` 只會被寫入一次。
2. **不遺漏 (Completeness)**：
   - 對任一天 `j`，設 `k` 是它右邊第一個嚴格更暖的日子。對於 `j < m < k` 的每一天，都有 `temperatures[m] <= temperatures[j]`，所以它們都無法彈出 `j`；而 `k` 到來時，`j` 上方的元素都比 `j` 冷或同溫（堆疊遞減），也都比 `k` 冷，會先被彈掉，接著 `j` 必被彈出且 `answer[j] = k - j`，正好是答案。
   - 若 `j` 右邊沒有更暖的日子，它永遠不會被彈出，`answer[j]` 維持初始值 0，符合題意。
3. **邊界條件**：
   - 單一元素 `[100]`：直接推入、迴圈結束，回傳 `[0]`。
   - 全同溫 `[30,30,30]`：嚴格大於的條件永遠不成立，全部留在堆疊，回傳 `[0,0,0]`。
   - 嚴格遞增 `[30,40,50]`：每一天都立刻結算前一天，堆疊最多一個元素，回傳 `[1,1,0]`。
   - 嚴格遞減 `[50,40,30]`：沒有任何彈出，堆疊長到 $N$，回傳全 0。

---

## 複雜度分析

- **Time Complexity**: $O(N)$
  - 其中 $N$ 為 `temperatures` 的長度。雖然 `for` 裡面包著 `while`，但每個 index 最多被推入一次、彈出一次，`while` 在整個過程中總共最多執行 $N$ 次彈出，屬於攤銷 (Amortized) $O(N)$。最好與最壞情況都是 $O(N)$。
- **Space Complexity**: $O(N)$
  - 輸出陣列 `answer` 本身是 $O(N)$（通常不計入額外空間）。
  - 額外空間來自堆疊：最好情況是嚴格遞增輸入，堆疊最多只有 1 個元素，$O(1)$；最壞情況是嚴格遞減輸入，所有 index 都堆在裡面，$O(N)$。

---

## 常見誤區

1. **比較條件寫成 `>=`**：同溫的日子不是「更暖」。若寫成 `t >= temperatures[stack[-1]]`，`[30,30,30]` 會得到 `[1,1,0]` 而非正確的 `[0,0,0]`。
2. **堆疊存溫度而不是 index**：彈出時要算 `i - j` 才能得到天數，只存溫度就無從得知那是哪一天，也無法寫回 `answer` 的正確位置。存 index 後溫度隨時可用 `temperatures[j]` 查回。
3. **把 `while` 寫成 `if`**：新的一天可能一次結算好幾天（trace 中 `i = 5` 一次彈出 69 與 71、`i = 6` 一次彈出 72 與 75）。用 `if` 只彈一個，後面那些天就會漏填，答案留在錯誤的 0。
4. **以為巢狀迴圈就是 $O(N^2)$**：分析 `for` + `while` 時要看「總操作次數」而非「每層最多幾次」。每個元素進出堆疊各一次，總成本是 $O(N)$。
5. **暴力解在大輸入下超時**：$N = 10^5$ 且輸入遞減時，雙層迴圈約 $5 \times 10^9$ 次比較，必然 TLE。

## 延伸思考

### 由右往左掃、利用已知答案跳躍 ($O(1)$ 額外空間)
如果面試官要求不用堆疊，可以從右往左算，並利用「右邊的答案已經算好」來跳躍：

- 想找第 `i` 天的下一個更暖日子，先看 `i + 1`。如果它不夠暖，那麼 `i + 1` 與它的下一個更暖日子 `i + 1 + answer[i + 1]` 之間的日子都不比 `temperatures[i + 1]` 暖，自然也不會比 `temperatures[i]` 暖，可以直接跳過。
- 維護目前看過的最高溫 `hottest`：若第 `i` 天 `>= hottest`，右邊不可能有更暖的日子，`answer[i] = 0`，並更新 `hottest`。這也保證了跳躍迴圈一定會停在某個更暖的日子上，不會跳出陣列。

```python
class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        answer = [0] * n
        hottest = 0

        for i in range(n - 1, -1, -1):
            t = temperatures[i]
            # 右邊沒有比它更高的溫度，答案就是 0
            if t >= hottest:
                hottest = t
                continue
            days = 1
            # 不夠暖就直接跳到「那一天的下一個更暖日子」，跳過中間必然更冷的區段
            while temperatures[i + days] <= t:
                days += answer[i + days]
            answer[i] = days

        return answer
```

時間仍為攤銷 $O(N)$，額外空間降為 $O(1)$（不計輸出陣列）。

### 利用溫度值域
溫度只在 30–100 之間，也可以從右往左掃，維護 `next_index[temp]` 記錄每個溫度最近出現的位置，對每一天枚舉所有更高的溫度取最小 index，時間為 $O(N \cdot W)$，$W = 71$ 為值域大小。這在值域小時可行，但單調堆疊不依賴值域，是更通用的解法。

## 小結

這題是「下一個更大元素 (Next Greater Element)」的經典應用，也是單調堆疊最標準的入門題。

**核心觀念：**
- 「替每個元素找左／右邊第一個比它大／小的元素」幾乎都可以用單調堆疊在 $O(N)$ 內解決。
- 堆疊存 index 而非值，才能同時取得距離與原值。
- `for` 包 `while` 的複雜度要用攤銷分析：看每個元素總共進出幾次。
