## 題目描述 (中文摘要)
給定一個只包含 `(` `)` `{` `}` `[` `]` 的字串 `s`，判斷它是否為有效的括號字串。有效的條件：

1. 每個左括號都必須由**同類型**的右括號關閉。
2. 左括號必須以**正確的順序**關閉（後開的先關）。
3. 每個右括號都要有一個對應的左括號。

限制：`1 <= s.length <= 10^4`。

範例：
```
輸入：s = "()[]{}"   輸出：true
輸入：s = "(]"       輸出：false
輸入：s = "([)]"     輸出：false
輸入：s = "{[]}"     輸出：true
```

---

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
核心觀察：**最晚出現、還沒被關閉的左括號，一定是下一個右括號要配對的對象**——這正是「後進先出 (LIFO)」的結構。
1. **演算法選擇**：採用 **堆疊 (Stack)** 搭配一張「左括號 → 右括號」的對照表。
2. **具體步驟**：
   - 由左到右掃描字串。
   - 遇到左括號就 push 進堆疊，代表「這個括號還在等人關它」。
   - 遇到右括號就 pop 堆疊頂端，檢查頂端左括號對應的右括號是否就是目前這個；堆疊為空或對不上，立刻回傳 `False`。
   - 掃描結束後，堆疊必須為空，否則代表有左括號沒被關閉。

### English Interview Plan
The goal is to verify that every closing bracket matches the most recent unmatched opening bracket of the same type.
1. **Strategy**: Use a stack, because the bracket that must be closed next is always the last one opened (LIFO). This gives a single $O(N)$ pass.
2. **Execution**:
   - **Base Case**: An empty stack at the end means every opening bracket was matched.
   - **Iterative Step**: Push opening brackets; for a closing bracket, pop the top and check that it maps to the current character.
   - **Key Insight**: Fail fast when a closing bracket arrives with an empty stack or a mismatched top, and remember to check for leftover openers after the loop.

## 演算法詳解

直覺上可能會想「分別計算三種括號的數量是否相等」，但數量相等不代表順序正確，例如 `"([)]"` 每種括號都是一開一關，卻是無效的。也可以反覆把字串中的 `()`、`[]`、`{}` 刪掉直到不能再刪，但每輪都要重建字串，最壞是 $O(N^2)$。

堆疊的作用是**記住「目前還開著的左括號」以及它們開啟的順序**，讓每個右括號都能在 $O(1)$ 時間找到它唯一合法的配對對象。

### 狀態變化 (State Transitions)
以 `s = "{[]}"` 為例（`look_up = {"(": ")", "{": "}", "[": "]"}`）：

| 步驟 | 字元 | 動作 | 堆疊狀態 |
|---|---|---|---|
| 1 | `{` | 左括號，push | `['{']` |
| 2 | `[` | 左括號，push | `['{', '[']` |
| 3 | `]` | 右括號，pop 出 `[`，`look_up['['] == ']'` 吻合 | `['{']` |
| 4 | `}` | 右括號，pop 出 `{`，`look_up['{'] == '}'` 吻合 | `[]` |
| 結束 | — | 堆疊為空 → 回傳 `True` | `[]` |

再看失敗案例 `s = "([)]"`：

| 步驟 | 字元 | 動作 | 堆疊狀態 |
|---|---|---|---|
| 1 | `(` | push | `['(']` |
| 2 | `[` | push | `['(', '[']` |
| 3 | `)` | pop 出 `[`，`look_up['['] == ']'`，與 `)` 不符 → 回傳 `False` | `['(']` |

第 3 步就是「數量相等但順序錯」被抓出來的地方：`)` 想關的是 `(`，但最晚開的是 `[`，必須先關 `[` 才行。

## 程式碼實作

```python
class Solution:
    def isValid(self, s: str) -> bool:
        # 用「左 → 右」的方向建表：pop 出左括號後可直接查它「應該」被誰關閉
        look_up = {"(": ")", "{": "}", "[": "]"}
        S = []
        for i in s:
            if i in look_up:
                # 左括號先存起來，等之後的右括號來關
                S.append(i)
            else:
                # 先檢查 not S：右括號出現時若沒有任何開著的左括號，pop 會丟 IndexError
                # 利用 or 的短路求值，S 為空時不會執行到 pop
                if not S or look_up[S.pop()] != i:
                    return False
        # 掃完還有剩的左括號，代表有括號沒被關閉，例如 "(("
        return not S
```

## 正確性說明

1. **不重複 (No Redundancy)**：每個字元只被掃描一次；每個左括號最多被 push 一次、pop 一次，配對成功後即從堆疊移除，不會被第二個右括號重複使用。
2. **不遺漏 (Completeness)**：三條有效規則各有對應的檢查——
   - 「同類型關閉」：`look_up[S.pop()] != i` 檢查類型。
   - 「正確順序」：堆疊頂端永遠是最晚開啟、尚未關閉的左括號，只允許它被關閉。
   - 「每個右括號都有對應」：`not S` 擋下多出來的右括號；結尾的 `return not S` 擋下多出來的左括號。
3. **邊界條件**：
   - 只有右括號（如 `")"`）：第一個字元就遇到空堆疊，回傳 `False`。
   - 只有左括號（如 `"(("`）：迴圈中不會 return，但結尾堆疊非空，回傳 `False`。
   - 長度為奇數（如 `"(()"`）：不可能兩兩配對，最後一定會剩下左括號或遇到空堆疊，回傳 `False`。

---

## 複雜度分析

- **Time Complexity**: $O(N)$
  - 其中 $N$ 為字串 `s` 的長度。每個字元只做一次字典查詢與至多一次 push/pop，皆為 $O(1)$。
  - 最好情況：第一個字元就是右括號（如 `")..."`），$O(1)$ 即回傳；最壞情況：整串有效或錯誤出現在最後，需掃完全部 $N$ 個字元。
- **Space Complexity**: $O(N)$
  - 空間來自堆疊 `S`，大小等於「同時開著的左括號數量」。
  - 最好情況：如 `"()()()"`，堆疊最多只放 1 個元素，$O(1)$；最壞情況：如 `"(((((("`，所有字元都被 push，$O(N)$。對照表 `look_up` 固定 3 筆，為 $O(1)$。

## 常見誤區

1. **只計數不看順序**：用三個計數器統計各類括號是否一開一關，會把 `"([)]"` 誤判為有效。計數只適用於「只有一種括號」的情況（例如只有 `()` 時，用一個整數 `balance` 就夠，且要在途中檢查 `balance < 0`）。
2. **pop 前沒檢查堆疊是否為空**：寫成 `if look_up[S.pop()] != i` 而少了 `not S`，輸入 `"]"` 時會直接拋出 `IndexError`。`not S` 必須寫在 `or` 的**左邊**，靠短路求值保護 pop；順序反過來一樣會炸。
3. **迴圈結束直接 `return True`**：忘了檢查堆疊是否還有剩，`"(("`、`"{[]"` 這類「左括號多出來」的輸入會被誤判為有效。
4. **對照表方向搞反卻沒改比較邏輯**：若建成「右 → 左」的表（`{")": "("}`），判斷左括號要改用 `i not in table`（或 `i in table.values()`），比較也要改成 `S.pop() != table[i]`。混用兩種方向是常見的錯誤來源，建表時先決定好「pop 出來的東西要拿去查什麼」。

## 小結

這題是堆疊 (Stack) 最經典的入門題：凡是「最近開啟的必須最先關閉」的巢狀結構，都可以用堆疊處理。

**核心觀念：**
- 巢狀結構的配對關係天生是後進先出 (LIFO)，堆疊頂端就是下一個必須被關閉的對象。
- 檢查要三面俱到：類型是否對得上、遇到右括號時堆疊是否為空、掃描結束後堆疊是否清空。
- 數量正確不代表順序正確，多種括號混用時計數法會失效。
