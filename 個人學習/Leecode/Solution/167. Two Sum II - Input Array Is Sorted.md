## 題目描述 (中文摘要)
給定一個 **1-indexed**、已按**非遞減順序排序**的整數陣列 `numbers`，以及目標值 `target`。
找出兩個數字使其和等於 `target`，回傳它們的索引 `[index1, index2]`（皆 +1，且 `index1 < index2`）。
- 題目保證**恰好只有一組解**，且同一個元素不能使用兩次。
- 限制：只能使用**常數額外空間**。
- `2 <= numbers.length <= 3 * 10^4`，`-1000 <= numbers[i], target <= 1000`。

範例：
```
輸入：numbers = [2, 7, 11, 15], target = 9
輸出：[1, 2]   # 2 + 7 = 9，回傳 1-indexed 位置
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
陣列已排序，代表「兩端相加」的結果可以告訴我們下一步該往哪個方向調整，不需要額外的 Hash Map。
1. **演算法選擇**：採用 **對撞雙指標 (Opposite / Two Pointers)**。
2. **具體步驟**：
   - `left` 指向最小值（開頭）、`right` 指向最大值（結尾）。
   - 計算 `s = numbers[left] + numbers[right]`。
   - `s == target` → 回傳 `[left + 1, right + 1]`。
   - `s < target` → 和太小，只能靠換更大的左值補，`left += 1`。
   - `s > target` → 和太大，只能靠換更小的右值減，`right -= 1`。

### English Interview Plan
We need to find the unique pair that sums to `target` using only $O(1)$ extra space.
1. **Strategy**: Because the array is sorted, place one pointer at each end and move them toward each other. Each comparison eliminates one element, giving $O(N)$ time and $O(1)$ space.
2. **Execution**:
   - **Base Case**: If `numbers[left] + numbers[right] == target`, return the 1-indexed positions.
   - **Iterative Step**: If the sum is too small, advance `left`; if too large, retreat `right`.
   - **Key Insight**: When the sum is too small, `numbers[left]` paired with the largest remaining value still falls short, so `numbers[left]` can never be part of the answer and is safely discarded (symmetric for `right`).

## 演算法詳解

暴力解是雙層迴圈枚舉所有組合，時間 $O(N^2)$；第 1 題 Two Sum 的 Hash Map 解法雖然是 $O(N)$ 時間，卻需要 $O(N)$ 空間，違反本題「常數額外空間」的限制。
對撞雙指標利用「已排序」這個條件，每一步都能**確定地排除一個元素**，因此只需線性掃描一次。

為什麼可以排除？假設目前區間是 `[left, right]`：
- 若 `numbers[left] + numbers[right] < target`：`numbers[right]` 已經是區間內最大的值，連它都補不夠，`numbers[left]` 和區間內任何人配對都不可能等於 `target` → 丟掉 `left`。
- 若 `numbers[left] + numbers[right] > target`：`numbers[left]` 已經是區間內最小的值，連它都壓不下來，`numbers[right]` 不可能是答案 → 丟掉 `right`。

### 狀態變化 (State Transitions)
以 `numbers = [1, 3, 4, 5, 7, 11]`, `target = 9` 為例：

| 步驟 | left | right | numbers[left] + numbers[right] | 比較 | 動作 |
|---|---|---|---|---|---|
| 1 | 0 | 5 | 1 + 11 = 12 | > 9 | `right -= 1`（11 出局） |
| 2 | 0 | 4 | 1 + 7 = 8 | < 9 | `left += 1`（1 出局） |
| 3 | 1 | 4 | 3 + 7 = 10 | > 9 | `right -= 1`（7 出局） |
| 4 | 1 | 3 | 3 + 5 = 8 | < 9 | `left += 1`（3 出局） |
| 5 | 2 | 3 | 4 + 5 = 9 | == 9 | 回傳 `[3, 4]` |

每一步都讓區間縮小 1，最多 $N - 1$ 步就會碰到答案。

## 程式碼實作

```python
class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        left, right = 0, len(numbers) - 1

        # 用 < 而非 <=：同一個元素不能用兩次，left == right 時已無合法配對
        while left < right:
            s = numbers[left] + numbers[right]
            if s == target:
                # 題目要求 1-indexed
                return [left + 1, right + 1]
            if s < target:
                # numbers[right] 是區間最大值仍不夠，numbers[left] 不可能是答案
                left += 1
            else:
                # numbers[left] 是區間最小值仍太大，numbers[right] 不可能是答案
                right -= 1

        # 題目保證有解，理論上不會執行到這裡
        return []
```

## 正確性說明

1. **不重複 (No Redundancy)**：每次迴圈只移動一個指標，區間嚴格縮小 1，每個元素最多被當成「被排除者」一次，不會重複檢查同一組配對。
2. **不遺漏 (Completeness)**：設答案為 `(i, j)`，`i < j`。證明兩個指標都不會越過答案：
   - `right` 要越過 `j`，必須在 `right == j`、`left <= i` 時出現 `numbers[left] + numbers[j] > target`。但 `numbers[left] <= numbers[i]`，和最多等於 `target`，矛盾。
   - 對稱地，`left` 要越過 `i`，必須在 `left == i`、`right >= j` 時出現 `numbers[i] + numbers[right] < target`。但 `numbers[right] >= numbers[j]`，和至少等於 `target`，矛盾。
   - 區間每輪縮小 1 且兩端都不會越過答案，因此指標必定停在 `(i, j)` 並回傳。
3. **邊界條件**：
   - 長度為 2：一開始 `left = 0, right = 1`，直接檢查唯一組合。
   - 有重複值，如 `[0, 0, 3, 4]`, `target = 0`：第一輪 0 + 4 > 0 左移 `right`，一路縮到 `left = 0, right = 1`，回傳 `[1, 2]`，因為是不同索引所以合法。
   - 含負數，如 `[-3, -1, 2, 5]`, `target = -4`：排序性質不受正負影響，照樣成立。

---

## 複雜度分析

- **Time Complexity**: $O(N)$
  - 其中 $N$ 為 `numbers` 的長度。每輪迴圈區間縮小 1，最壞情況（答案在正中間相鄰兩格）需要 $N - 1$ 輪；最好情況是頭尾剛好就是答案，$O(1)$。
- **Space Complexity**: $O(1)$
  - 只使用 `left`、`right`、`s` 三個變數，不隨輸入大小增長，符合題目的常數空間限制。

## 常見誤區

1. **忘記 1-indexed**：直接回傳 `[left, right]` 會全部差 1，範例 `[2, 7, 11, 15]` 會得到 `[0, 1]` 而被判錯。
2. **迴圈條件寫成 `left <= right`**：本題保證有解，指標會在相遇前找到答案，所以這個寫法恰好能 AC，但語意是錯的：`left == right` 時會把同一個元素加兩次。換到「不保證有解」的變形就會出事，例如 `numbers = [1, 5, 8]`, `target = 10`：1 + 8 = 9 → `left` 右移；5 + 8 = 13 → `right` 左移；此時 `left == right == 1`，5 + 5 = 10，回傳 `[2, 2]` 這種不合法答案。
3. **照搬第 1 題的 Hash Map 解法**：能 AC，但空間是 $O(N)$，直接違反題目「常數額外空間」的要求，面試中會被追問為何沒利用排序條件。
4. **一次同時移動兩個指標**：以為「不相等就兩邊都縮」可以更快，實際上會跳過答案。例如 `[1, 2, 3, 4]`, `target = 6`：1 + 4 = 5 < 6，若兩邊同時縮變成 2 + 3 = 5，再縮一次指標就交錯了，錯過真正的答案 2 + 4。
5. **比較方向寫反**：`s < target` 時去移 `right`，區間會往更小的和收斂，永遠找不到答案，最後掉出迴圈回傳空陣列。

## 延伸思考

- **二分搜尋 (Binary Search) 版本**：固定 `numbers[i]`，在 `i + 1` 之後二分搜尋 `target - numbers[i]`。空間同樣 $O(1)$，但時間是 $O(N \log N)$，比雙指標差，適合拿來說明「為什麼雙指標是更好的選擇」。
- **擴展到 K-Sum**：3Sum 是「外層固定一個數 + 內層跑本題的雙指標」，時間 $O(N^2)$；4Sum 再多包一層。本題就是 K-Sum 家族的最底層元件。
- **換成求「最接近」或「計數」**：雙指標的排除邏輯不變，只是把 `==` 的處理改成更新最佳解（3Sum Closest）或累加數量（計算和小於 `target` 的配對數時，一次可加 `right - left` 組）。
- **若輸入是 BST 而非陣列**：可用中序遍歷的正向與反向迭代器模擬左右指標，達到 $O(H)$ 空間（LeetCode 653）。

## 小結

這題是**對撞雙指標**的標準入門題，重點在於理解「已排序」如何讓每一步都能安全地排除一個元素。

**核心觀念：**
- 排序陣列上找配對，優先考慮從兩端往中間收斂的雙指標，而不是 Hash Map。
- 移動指標的依據是「目前區間的極值都無法配出答案」，這是正確性證明的核心。
- 注意題目細節：1-indexed 回傳、同元素不能重複使用（`left < right`）。
