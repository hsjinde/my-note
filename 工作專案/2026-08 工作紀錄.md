- **清掉 Blog 測試殘留、建立發文管道**（8/4，清單第 1 項）：新增 `publish-post.mjs` 發文 CLI 取代手動對 D1 下 SQL，清掉 `hello-d1` 連線測試文與標題還留佔位符的文章；改寫 AI 吉祥物那篇的內容（原文通篇在講已於 7/18 移除的浮動 widget，現況是 `/ask` 全頁）。順手在 README 標明 `docs/posts` 不是 D1 的完整鏡像，避免下次誤以為改檔案就會上站
- **線上淺色模式完全失效**（8/4）：`index.html` 的 theme bootstrap 是 inline script，被 CSP 擋掉，線上點切換鈕毫無反應——本地看不出來，因為 dev server 沒套 `public/_headers`。改為外部檔 `theme-init.js`，並在 e2e 加 `data-theme` 防復發斷言
- **postType 型別漂移**（8/4）：`postType` 一路被放寬成任意字串，前台遇到未知型別直接空白。收斂回 `PostType` union、未知型別改標「未分類」，同時在 `cloudflare-use` skill 的 `d1-insert-post.cjs` 加白名單驗證——擋在寫入端才不會再髒進 D1
- **CI 閘門**（8/4，清單第 5 項）：lint/test 補進 workflow，新增 e2e job（`ask` / `theme`）
- **SEO 從零補起**（8/7，清單第 2 項，槓桿最大的一項）：原本 `robots.txt` / `sitemap.xml` 都不存在、只是被 SPA fallback 接走，10 篇文章共用同一組 meta，等於對爬蟲與社群預覽不存在。改用 Pages Function middleware 在 edge 注入每篇的 og meta 與 JSON-LD，加上產生 sitemap 與預設 og 圖的腳本；隨後修掉 meta 覆寫後沒清 ETag、導致回訪拿 304 配到舊標題的問題
- **README 重寫**（8/8）：同步到 Terminal Editorial 現況
- **無障礙契約自動化**（8/8）：修掉四條 WCAG A/AA 違規（`TerminalCard`、`AsciiMeter`、`ScopeDeck`、`Ask` 頁），並把 axe 掃描與 `PRODUCT.md` 裡的無障礙契約寫成 e2e 斷言——重點在後者，讓設計文件寫的東西變成 CI 會擋的條件，而不是靠人記得

## 2. VPS 安全巡檢（8/1）

用 `server-security-audit` skill 對自架 VPS 做例行巡檢，掃 Docker、防火牆／SSH／fail2ban、mail server 三塊。10 個容器與既有記錄相符，沒有新增對外綁定；SSH 歷來成功登入全數來自已知金鑰。

- **找到並修好一個真實漏洞**：`postfix-docker` jail 的 regex 寫成 `postfix/\w+\[`，只匹配得到 25 埠的 `postfix/smtpd`。Postfix 的 submission／smtps 監聽器叫 `postfix/submission/smtpd`、`postfix/smtps/smtpd`，中間那個 `/` 不是 `\w`——**587 與 465 埠上的每一筆 SASL 認證失敗都被靜默漏掉**
- 陰險之處在於封鎖歷史看不出破綻：攻擊來源 7/22 還在打 25 埠時有被正常封鎖過，之後整批搬到 587。7/25–8/1 這週 96% 的攻擊 fail2ban 完全沒看到，兩個分散式字典攻擊網段每個 IP 每天約 7 次、早已超過 `maxretry=5` 卻一次都沒被封
- 修法與驗證：regex 改 `postfix/(?:\w+/)?\w+\[`，`fail2ban-regex` 全日誌從 13135 → 13972（+837，正好等於漏掉的 784+53，舊有的一筆沒少）；`reload` 即可不必重啟；另塞合成 log 做端到端實測確認真的在計數。同時確認 `dovecot-docker` 沒有同類問題
- 教訓：**「有在跑」不等於「看得到」**。三個 jail 狀態全綠、封鎖數字也在增加，光看儀表板永遠發現不了這個洞——要對照原始日誌的實際筆數才抓得出來
- 相關背景見 [[Postfix-Manager-技術分享筆記]]
