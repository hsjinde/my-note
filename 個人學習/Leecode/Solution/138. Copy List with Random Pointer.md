## 題目描述 (中文摘要)
給定長度為 `n` 的鏈結串列，每個節點除了 `next`，還多一個 `random` 指標，可指向串列中任一節點（包含自己）或 `null`。

請建立這個串列的深拷貝 (Deep Copy)：恰好 `n` 個全新節點，值與對應的原節點相同，`next` 和 `random` 都只能指向新串列的節點，不能指回原串列。回傳新串列的 head。

限制：$0 \le n \le 1000$，$-10^4 \le$ `Node.val` $\le 10^4$。

輸入輸出以 `[val, random_index]` 表示每個節點，但函式實際只會拿到 head，拿不到 index。

範例：
```
輸入：head = [[7,null],[13,0],[11,4],[10,2],[1,0]]
輸出：[[7,null],[13,0],[11,4],[10,2],[1,0]]
```
輸出長得和輸入一樣，差別在於節點都是新建的。

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
難點在於複製某個節點時，它的 `random` 可能指向還沒建立的節點，所以要先解決「舊節點如何對應到新節點」。
1. **演算法選擇**：採用 **HashMap 兩趟走訪 (Two-pass with Hash Map)**；要壓低額外空間時，改用 **交織複製 (Interweaving Nodes)**。
2. **具體步驟**：
   - HashMap 版：第一趟只建節點並記下 `舊 -> 新`，第二趟查表接上 `next` 與 `random`。
   - 交織版：把複本插在原節點後面（`A -> A' -> B -> B'`），讓 `舊節點.next` 取代 HashMap。
   - 交織版接著用 `cur.random.next` 設定複本的 `random`，最後拆開兩條串列並還原原串列。

### English Interview Plan
The goal is to deep copy a linked list whose nodes also have a random pointer that may reference any node, including one not yet copied.
1. **Strategy**: Separate node creation from pointer wiring. A hash map gives $O(N)$ time and $O(N)$ extra space; interweaving the copies into the original list keeps $O(N)$ time with $O(1)$ extra space.
2. **Execution**:
   - **Base Case**: An empty list returns `None`. The hash map version handles this by seeding the map with `{None: None}`.
   - **Iterative Step**: Create every copy first, then set each copy's `next` and `random` through the old-to-new mapping.
   - **Key Insight**: The mapping does not have to be a hash map. Placing each copy right after its original makes `original.next` the mapping, so `copy.random = original.random.next`.

## 演算法詳解

只照 `next` 走一趟複製，遇到往後指的 `random` 時目標節點還不存在，這條指標就接不上。每次都從 head 重新找目標則是 $O(N^2)$，而且值可能重複，也無法靠值來找。

兩個版本都是先讓所有複本存在，再接指標，差別只在如何保存 `舊 -> 新` 的對應。

### 狀態變化 (State Transitions)
以 `[[7,2],[13,0],[11,null]]` 為例，三個節點記為 `A(7)`、`B(13)`、`C(11)`，其中 `A.random = C`、`B.random = A`、`C.random = None`。`A` 的 `random` 往後指，正好是一趟複製處理不了的情況。

**HashMap 版：**
1. 第一趟建表：`{None: None, A: A', B: B', C: C'}`，此時複本的指標都還是空的。
2. 第二趟 `cur = A`：`A'.next = B'`、`A'.random = C'`。`C'` 雖然在後面，但第一趟已經建好，查得到。
3. 第二趟 `cur = B`：`B'.next = C'`、`B'.random = A'`。
4. 第二趟 `cur = C`：`C'.next = map[None] = None`、`C'.random = None`。
5. 回傳 `map[A] = A'`。

**交織版：**
1. 第一趟插入複本：`A -> A' -> B -> B' -> C -> C' -> None`。
2. 第二趟 `cur = A`：`A'.random = A.random.next = C.next = C'`。
3. 第二趟 `cur = B`：`B'.random = B.random.next = A.next = A'`。
4. 第二趟 `cur = C`：`C.random` 是 `None`，跳過，`C'.random` 維持 `None`。
5. 第三趟先記下 `new_head = A'`，再逐一拆開：
   - `cur = A`：`A.next = B`、`A'.next = B'`。
   - `cur = B`：`B.next = C`、`B'.next = C'`。
   - `cur = C`：`C.next = None`、`C'.next = None`。
6. 得到 `A' -> B' -> C'`，原串列也還原成 `A -> B -> C`。

## 程式碼實作

### HashMap 兩趟走訪版本

```python
"""
# Definition for a Node.
class Node:
    def __init__(self, x: int, next: 'Node' = None, random: 'Node' = None):
        self.val = int(x)
        self.next = next
        self.random = random
"""

class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        # 放入 None: None，尾節點的 next 和空的 random 就不用另外判斷
        old_to_new = {None: None}

        # 第一趟只建節點：random 可能往後指，要先讓所有複本都存在
        cur = head
        while cur:
            old_to_new[cur] = Node(cur.val)
            cur = cur.next

        # 第二趟才接指標：此時任何舊節點都查得到對應的複本
        cur = head
        while cur:
            copy = old_to_new[cur]
            copy.next = old_to_new[cur.next]
            copy.random = old_to_new[cur.random]
            cur = cur.next

        return old_to_new[head]
```

### 交織複製版本

```python
"""
# Definition for a Node.
class Node:
    def __init__(self, x: int, next: 'Node' = None, random: 'Node' = None):
        self.val = int(x)
        self.next = next
        self.random = random
"""

class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        if not head:
            return None

        # 把複本插在原節點後面，讓 舊節點.next 取代 HashMap 的對應關係
        cur = head
        while cur:
            cur.next = Node(cur.val, cur.next)
            cur = cur.next.next

        # random 要等交織全部完成才能設，否則 cur.random.next 可能還不是複本
        cur = head
        while cur:
            if cur.random:
                cur.next.random = cur.random.next
            cur = cur.next.next

        # 拆分要獨立一趟：提早拆開會破壞後面節點查 cur.random.next 所需的結構
        new_head = head.next
        cur = head
        while cur:
            copy = cur.next
            cur.next = copy.next
            # 最後一個複本的 copy.next 是 None，不能再往下取 .next
            copy.next = copy.next.next if copy.next else None
            cur = cur.next

        return new_head
```

## 正確性說明

1. **不重複 (No Redundancy)**：
   - 兩個版本都只在第一趟建立節點，每個原節點恰好對應一個複本。
   - 多個節點的 `random` 指向同一目標時，都會接到同一個複本，不會多建。
2. **不遺漏 (Completeness)**：
   - 第一趟沿 `next` 走完整條串列，而 `random` 只會指向串列內的節點，所以接指標時一定找得到複本。
   - 每個複本的 `next`、`random` 都在第一趟之後才設定，往前指、往後指或指向自己都能處理。
   - 新指標一律取自對應關係或 `舊節點.next`，因此只會指向複本，不會指回原串列。
3. **邊界條件**：
   - 空串列：HashMap 版回傳 `old_to_new[None]`，也就是 `None`；交織版直接回傳 `None`。
   - 單一節點且 `random` 指向自己（`[[1,0]]`）：交織版算出 `A'.random = A.next = A'`，複本指向自己。
   - 所有值都相同（`[[3,null],[3,0],[3,null]]`）：對應關係以節點物件為依據，不受重複值影響。

## 時間複雜度分析

- **Time Complexity**: 兩個版本都是 $O(N)$
  - 其中 $N$ 為串列的節點數。
  - HashMap 版走兩趟，每個節點做常數次字典操作（平均 $O(1)$）。
  - 交織版走三趟，每趟只做指標操作，沒有雜湊成本。
  - 最好與最壞情況相同：每個節點都一定要複製，走訪趟數也固定，不會因 `random` 的指向而改變。只有 $N = 0$ 時會立刻結束。

---

## 空間複雜度分析

輸出的 $N$ 個新節點是題目要求，兩個版本都無法省略，以下只計算額外空間。

- **HashMap 版**：$O(N)$ 額外空間
  - 字典存放 $N + 1$ 筆對應（$N$ 個節點加上 `None`），最好與最壞情況相同。
- **交織版**：$O(1)$ 額外空間
  - 只用了幾個指標變數，最好與最壞情況相同。對應關係直接存在串列結構裡。
  - 代價是執行期間會暫時改動輸入的串列。

## 常見誤區

1. **用 `val` 當 HashMap 的 key**：題目允許重複值，`[[3,null],[3,0],[3,null]]` 三個節點會擠成同一筆對應，複本數量和指標都會錯。key 必須是節點物件本身。
2. **一趟邊建邊接 `random`**：`random` 往後指時目標還不存在。若當下直接 `new Node` 卻沒存進對應表，之後走到該節點又會再建一個，同一節點變成兩個複本。
3. **複本的 `random` 指回原節點**：寫成 `copy.random = cur.random` 就成了淺拷貝 (Shallow Copy)。只印 `val` 看不出來，但違反題目要求。
4. **交織版在 `cur.random` 為 `None` 時取 `.next`**：`cur.random.next` 會丟出 `AttributeError`，要先判斷。HashMap 版靠 `{None: None}` 避開了這個問題。
5. **交織版把設定 `random` 和拆分寫在同一趟**：前面的節點一拆開，`next` 就不再指向複本。後面節點的 `random` 若往前指，`cur.random.next` 會取到錯的節點。
6. **交織版沒有還原原串列**：只取出複本、不改回 `cur.next`，原串列就會殘留複本節點。這等於改壞了呼叫端傳入的資料，即使回傳的複本完全正確也一樣。
7. **認為交織版一定比較好**：它省下字典，卻要暫時改動輸入。輸入是唯讀、或有其他執行緒同時在讀時就不適用。面試時可以先講 HashMap 版，再提交織版作為空間最佳化。

## 小結

這題屬於「複製含任意指標的結構」，重點是維持 `舊 -> 新` 的對應，和複製圖是同一類問題。

**核心觀念：**
- 把「建立節點」和「接指標」分開，就不必擔心目標節點還沒建立。
- 對應關係不一定要用 HashMap，把複本插在原節點後面，`舊節點.next` 就是對應關係，額外空間從 $O(N)$ 降到 $O(1)$。
- 就地修改輸入時，要在回傳前還原，並且清楚這個做法的適用限制。
