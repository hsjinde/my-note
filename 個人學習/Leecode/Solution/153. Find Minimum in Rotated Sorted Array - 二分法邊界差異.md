## 題目描述 (中文摘要)
一個長度 `n`、元素**互不相同**的遞增陣列，被旋轉了 `1 ~ n` 次（旋轉一次是把最後一個元素移到最前面；旋轉 `n` 次等於沒轉）。給定旋轉後的 `nums`，回傳其中的最小值，要求時間複雜度 $O(\log n)$。

限制：`1 <= n <= 5000`，`-5000 <= nums[i] <= 5000`，所有元素互不相同。

範例：
```
輸入：nums = [3, 4, 5, 1, 2]          輸出：1
輸入：nums = [4, 5, 6, 7, 0, 1, 2]    輸出：0
輸入：nums = [11, 13, 15, 17]         輸出：11   （轉了 n 次，等於沒轉）
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
旋轉後的陣列是「左段遞增 + 右段遞增」，而且左段每個值都大於右段每個值。最小值就是右段的開頭，也就是兩段的**斷點**。只要每輪判斷 `mid` 落在哪一段，就能丟掉一半。
1. **演算法選擇**：採用 **二分搜尋 (Binary Search)**，用 `nums[m]` 與 `nums[l]` 比較來判斷 `m` 落在左段還是右段。
2. **具體步驟**：
   - 若 `nums[l] < nums[r]`，代表 `[l, r]` 這段沒有斷點、本身已排序，`nums[l]` 就是這段的最小值。
   - 否則取 `m`：`nums[m] >= nums[l]` 代表 `m` 在左段，最小值在 `m` 右邊，令 `l = m + 1`。
   - `nums[m] < nums[l]` 代表 `m` 在右段，最小值在 `m` 或 `m` 左邊。
   - 這一步有兩種寫法，差別就在**要不要把 `m` 留在區間裡**：
     - 記錄答案版：`r = m - 1`，丟掉 `m` 之前先用 `ans` 記下 `nums[m]`。
     - 收斂版：`r = m`，把 `m` 留在區間內，最後 `l == r` 時 `nums[l]` 就是答案。

### English Interview Plan
Find the minimum of a sorted array that has been rotated, in $O(\log n)$ time.
1. **Strategy**: A rotated sorted array consists of two increasing runs, and every value in the left run is larger than every value in the right run. The minimum is the first element of the right run, so binary search for that break point.
2. **Execution**:
   - **Early Exit**: If `nums[l] < nums[r]`, the window is already sorted and `nums[l]` is its minimum.
   - **Iterative Step**: If `nums[m] >= nums[l]`, `m` is in the left run, so search `[m+1, r]`. Otherwise `m` is in the right run and the answer is at `m` or to its left.
   - **Key Insight**: When `m` might itself be the answer, either keep it in the window (`r = m` with `while l < r`) or record it before discarding it (`ans = min(ans, nums[m])` then `r = m - 1`). Mixing the two drops the answer.

## 演算法詳解

暴力解是掃過整個陣列找最小值，$O(n)$，沒有用到「兩段各自有序」這個結構。

二分的關鍵是：拿 `nums[m]` 跟 `nums[l]` 比，就能知道 `m` 在哪一段。

```
nums = [5, 1, 2, 3, 4]
        └┘ └────────┘
      左段      右段（最小值 = 右段開頭）
```

- `nums[m] >= nums[l]`：`m` 跟 `l` 在同一段，也就是左段。左段的值全都比最小值大，`m` 本身不可能是答案，所以 `l = m + 1`。
- `nums[m] < nums[l]`：`m` 在右段。右段是遞增的，`m` 右邊不會更小，但 `m` **可能就是右段的開頭**，所以 `m` 不能直接丟掉。

「`m` 可能就是答案」正是兩種寫法分岔的地方。

### 狀態變化 (State Transitions)
以 `nums = [5, 1, 2, 3, 4]` 為例（答案是 `1`，位於索引 1）。

**收斂版（`while l < r`、`r = m`）：**

| 輪次 | l | r | `nums[l] < nums[r]`？ | m | nums[m] | 動作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 5 < 4 否 | 2 | 2 | 2 < 5，在右段，`r = 2` |
| 2 | 0 | 2 | 5 < 2 否 | 1 | 1 | 1 < 5，在右段，`r = 1` |
| 3 | 0 | 1 | 5 < 1 否 | 0 | 5 | 5 >= 5，在左段，`l = 1` |
| 結束 | 1 | 1 | — | — | — | `l == r`，回傳 `nums[1] = 1` |

**記錄答案版（`while l <= r`、`r = m - 1`、`ans` 初始為 `nums[0] = 5`）：**

| 輪次 | l | r | `nums[l] < nums[r]`？ | m | ans | 動作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 5 < 4 否 | 2 | min(5, 2) = 2 | 2 < 5，`r = 1` |
| 2 | 0 | 1 | 5 < 1 否 | 0 | min(2, 5) = 2 | 5 >= 5，`l = 1` |
| 3 | 1 | 1 | 1 < 1 否 | 1 | min(2, 1) = 1 | 1 >= 1，`l = 2` |
| 結束 | 2 | 1 | — | — | 1 | `l > r`，回傳 `ans = 1` |

第 1 輪 `r = m - 1` 把索引 2 丟掉了，但 `nums[2] = 2` 已經記進 `ans`，所以沒事。真正的答案索引 1 一直留在區間內，最後在第 3 輪被 `ans` 記到。

**錯誤組合：收斂版改成 `r = m - 1`**，以 `nums = [3, 1, 2]` 為例：

| 輪次 | l | r | `nums[l] < nums[r]`？ | m | nums[m] | 動作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 2 | 3 < 2 否 | 1 | 1 | 1 < 3，在右段，`r = 0` |
| 結束 | 0 | 0 | — | — | — | 回傳 `nums[0] = 3`，**錯誤** |

`m = 1` 正好就是答案，`r = m - 1` 把它丟出區間，又沒有 `ans` 記住它，答案就這樣消失了。前面幾組範例像 `[4,5,6,7,0,1,2]`、`[5,1,2,3,4]`，用錯誤組合也剛好能得到正確答案，所以光測範例很難發現這個 bug。

## 程式碼實作

### 記錄答案版 (Track Min)

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        ans = nums[0]
        l, r = 0, len(nums) - 1

        while l <= r:
            # 這段已排序，最左邊就是這段的最小值，不必再二分
            if nums[l] < nums[r]:
                ans = min(ans, nums[l])
                break

            m = (l + r) // 2
            # 下面兩個分支都會把 m 丟出區間，所以先把它記下來
            ans = min(ans, nums[m])
            if nums[m] >= nums[l]:
                l = m + 1
            else:
                r = m - 1

        return ans
```

### 收斂版 (Converge)

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        l, r = 0, len(nums) - 1

        while l < r:
            # 這段已排序，最左邊就是答案
            if nums[l] < nums[r]:
                return nums[l]

            m = (l + r) // 2
            if nums[m] >= nums[l]:
                l = m + 1
            else:
                # m 可能就是右段的開頭，不能丟掉
                r = m

        return nums[l]
```

兩版複雜度相同。收斂版不需要額外的 `ans`，迴圈結束時區間縮到剩一個元素，那個元素就是答案。記錄答案版的區間會一路清空，答案靠 `ans` 帶出來。

## 正確性說明

1. **不重複 (No Redundancy)**：
   - 收斂版：`l < r` 時 `m = (l + r) // 2` 嚴格小於 `r`，所以 `r = m` 與 `l = m + 1` 都讓區間嚴格縮小，迴圈一定會結束。
   - 記錄答案版：兩個分支都把 `m` 移出區間，每個索引最多被檢查一次。
2. **不遺漏 (Completeness)**：
   - 收斂版的不變式是「最小值的索引一定在 `[l, r]` 內」。`nums[m] >= nums[l]` 時，`l..m` 都在左段，比最小值大，可以安全丟掉；`nums[m] < nums[l]` 時，`m` 在右段，`m+1..r` 都比 `nums[m]` 大，丟掉它們但保留 `m`。
   - 記錄答案版的不變式是「`ans` 等於所有已被丟出區間的元素中的最小值，而且最小值要嘛已經在 `ans` 裡，要嘛還在 `[l, r]` 內」。
3. **邊界條件**：
   - 只有一個元素：收斂版不進迴圈，直接回傳 `nums[0]`；記錄答案版第一輪 `m = 0`，記下 `nums[0]` 後結束。
   - 轉了 `n` 次（等於沒轉，例如 `[11, 13, 15, 17]`）：第一次檢查 `nums[l] < nums[r]` 就成立，$O(1)$ 回傳。
   - 兩個元素且已旋轉（例如 `[2, 1]`）：`m = l = 0`，`nums[m] >= nums[l]` 以等號成立，所以 `l = 1`，正確得到 `1`。這也是條件必須寫 `>=` 的原因，見常見誤區第 3 條。
   - 最小值在最後一個位置（例如 `[2, 3, 4, 5, 1]`）：`l` 會一路往右推，直到 `l == r = 4`。

## 複雜度分析

- **Time Complexity**: $O(\log n)$
  - 其中 $n$ 為陣列長度，每輪區間至少砍半。
  - 最好情況 $O(1)$：陣列沒有旋轉（轉了 $n$ 次），或區間很快就縮到已排序的一段，`nums[l] < nums[r]` 直接成立。最壞情況 $O(\log n)$：斷點靠近陣列兩端，要一路縮到區間只剩一兩個元素。
- **Space Complexity**: $O(1)$
  - 只用了 `l`、`r`、`m`（與 `ans`）幾個變數。

## 常見誤區

1. **`r = m - 1` 卻沒有記錄答案**：收斂版把 `r = m` 改成 `r = m - 1` 後，`[3, 1, 2]` 會回傳 `3`。`nums[m] < nums[l]` 的分支裡 `m` 可能就是最小值，丟出區間前必須先記錄；不記錄就要用 `r = m` 把它留住。
2. **兩套模板混用**：`while l <= r` 搭配 `r = m`，`l == r` 時區間已經沒得縮，還會再跑一輪。收斂版這樣寫，`[2, 1]` 在 `l = r = 1` 時 `m = 1`、`nums[1] >= nums[1]` 成立，`l` 被推到 2，最後的 `nums[l]` 直接 `IndexError`。延伸思考的「跟右端比」版本這樣寫，`l == r` 時會走 `r = m`，區間不變，形成無窮迴圈。固定配對：`l < r` + `r = m` + 回傳 `nums[l]`；或 `l <= r` + `r = m - 1` + 回傳 `ans`。
3. **把 `>=` 寫成 `>`**：只剩兩個元素時 `m == l`，`nums[m]` 和 `nums[l]` 是同一個元素。以 `[2, 1]` 為例，寫成 `>` 會讓 `nums[0] > nums[0]` 不成立，走進 `r = m = 0`，回傳 `2`。`m == l` 時 `m` 屬於左段，必須用 `>=` 讓它走 `l = m + 1`。
4. **拿掉 `nums[l] < nums[r]` 的檢查**：跟 `nums[l]` 比的寫法依賴這個檢查。對沒有旋轉的 `[1, 2, 3]`，少了它會在第一輪得到 `nums[1] = 2 >= nums[0] = 1`，判定 `m` 在「左段」並令 `l = 2`，回傳 `3`。原因是已排序的區間根本沒有右段，「`m` 跟 `l` 同段就在左段」的推論不成立。改成跟 `nums[r]` 比就不需要這個檢查，見延伸思考。
5. **原本寫法的小冗餘**：舊版記錄答案版在迴圈前多做了一次 `if nums[l] < nums[r]: return nums[l]`。迴圈第一輪本來就會檢查同一件事，所以結果不變，只是重複；上面的程式碼已經拿掉。

## 延伸思考

### 跟右端比：不需要提早結束的寫法
把比較對象從 `nums[l]` 換成 `nums[r]`：

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        l, r = 0, len(nums) - 1

        while l < r:
            m = (l + r) // 2
            # nums[m] 比右端大，代表斷點在 m 右邊
            if nums[m] > nums[r]:
                l = m + 1
            else:
                # m 和 r 在同一個遞增段，m 可能就是最小值
                r = m

        return nums[l]
```

`nums[r]` 一定屬於右段（陣列沒轉的話，整個陣列都算右段），所以 `nums[m] > nums[r]` 必定代表 `m` 在左段，不需要 `nums[l] < nums[r]` 的特判，也沒有 `m == l` 的 `>=` 問題（`m < r` 恆成立，`m` 和 `r` 不會是同一個元素）。這是三個版本中最不容易寫錯的一個。

### 和 875 是同一套模板
把問題改寫成判斷式 `nums[i] <= nums[-1]`：左段每個值都大於 `nums[-1]`，右段每個值都小於等於它，所以判斷式在索引上長成 F…F T…T，最小值就是**第一個 `T`**。這跟 [[875. Koko Eating Bananas]] 找「第一個可行速度」是同一套 `lo < hi`、`hi = mid` 的 lower bound 模板，只是一個在索引上搜、一個在答案空間上搜。

### 有重複元素：154
LeetCode 154 允許重複值時，`nums[m] == nums[r]` 無法判斷 `m` 在哪一段（例如 `[1, 1, 1, 0, 1]` 和 `[1, 0, 1, 1, 1]`）。這時只能 `r -= 1` 一步一步縮，最壞情況退化成 $O(n)$。

## 小結

這題是在旋轉排序陣列上找斷點的二分搜尋題。重點不在判斷哪半邊有序，而在**中點可能就是答案時，邊界要怎麼收**。

**核心觀念：**
- 旋轉陣列 = 兩段遞增，左段全部大於右段；最小值是右段開頭。
- `m` 可能是答案時，要嘛 `r = m` 把它留在區間（搭配 `while l < r`），要嘛先記進 `ans` 再 `r = m - 1`（搭配 `while l <= r`），兩者不能混用。
- 跟 `nums[r]` 比可以省掉已排序的特判與 `>=` 的邊界問題，是最穩的寫法。
