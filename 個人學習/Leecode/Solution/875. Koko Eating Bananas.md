## 題目描述 (中文摘要)
有 `n` 堆香蕉，第 `i` 堆有 `piles[i]` 根。警衛 `h` 小時後回來。Koko 每小時挑**一堆**吃 `k` 根；若那堆不足 `k` 根，就把它吃完，**這一小時剩下的時間不會再去吃別堆**。

回傳能在 `h` 小時內吃完所有香蕉的**最小整數速度** `k`。

限制：`1 <= piles.length <= 10^4`，`piles.length <= h <= 10^9`，`1 <= piles[i] <= 10^9`。

範例：
```
輸入：piles = [3, 6, 7, 11], h = 8         輸出：4
輸入：piles = [30, 11, 23, 4, 20], h = 5   輸出：30
輸入：piles = [30, 11, 23, 4, 20], h = 6   輸出：23
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
速度 `k` 越快，需要的時數越少——「`k` 可不可行」對 `k` 是單調的，所以不用在陣列上二分，而是直接**對答案 `k` 二分**。
1. **演算法選擇**：採用 **對答案空間二分 (Binary Search on Answer)**，搜尋範圍是速度 `1 ~ max(piles)`。
2. **具體步驟**：
   - 設 `lo = 1`、`hi = max(piles)`；`hi` 一定可行，因為每堆一小時吃完只要 `n` 小時，而題目保證 `h >= n`。
   - 每輪取 `mid`，算出以速度 `mid` 吃完所需的時數：每堆 `ceil(p / mid)` 小時，加總。
   - 時數 `<= h` 代表 `mid` 可行，答案在 `[lo, mid]`，令 `hi = mid`；否則答案在 `[mid+1, hi]`，令 `lo = mid + 1`。
   - `lo == hi` 時收斂，`lo` 就是最小可行速度。

### English Interview Plan
Find the smallest integer eating speed `k` that lets Koko finish every pile within `h` hours.
1. **Strategy**: The predicate "speed `k` finishes within `h` hours" is monotonic in `k` (false…false, true…true), so binary search over the answer range `[1, max(piles)]` for the first `true`. Each check costs $O(n)$, giving $O(n \log M)$ overall.
2. **Execution**:
   - **Initialization**: `lo = 1`, `hi = max(piles)` — the upper bound is always feasible because `h >= len(piles)`.
   - **Iterative Step**: For `mid`, compute `sum(ceil(p / mid))`. If it is `<= h`, keep `mid` as a candidate with `hi = mid`; otherwise `lo = mid + 1`.
   - **Key Insight**: We are not searching an array; we are searching the space of possible answers, and the feasibility check is the "comparison" that tells us which half to discard.

## 演算法詳解

暴力解是從 `k = 1` 往上試，每個 `k` 花 $O(n)$ 算時數，最壞要試到 `max(piles)`，也就是 $O(n \cdot M)$；`M` 最大到 $10^9$，一定超時。

能二分的前提是**單調性**：定義

$$\text{hours}(k) = \sum_{i} \left\lceil \frac{piles[i]}{k} \right\rceil$$

`k` 變大時每一項 $\lceil p / k \rceil$ 只會變小或不變，所以 $\text{hours}(k)$ 隨 `k` **非遞增**。於是判斷式 `hours(k) <= h` 在 `k` 軸上長這樣：

```
k        :  1   2   3   4   5   6  ...  11
可行？   :  F   F   F   T   T   T  ...   T
```

前面一段全是 `F`、後面一段全是 `T`，要找的就是**第一個 `T`**。這跟 74. Search a 2D Matrix 找「某個值在不在」不同，是 lower bound 型的二分：命中時不能立刻回傳，因為左邊可能還有更小的可行速度，所以用 `hi = mid` 把 `mid` 留在區間內繼續縮。

### 狀態變化 (State Transitions)
以 `piles = [3, 6, 7, 11]`、`h = 8` 為例，初始 `lo = 1`、`hi = 11`。

| 輪次 | lo | hi | mid | 各堆時數 `ceil(p/mid)` | 總時數 | 動作 |
|---|---|---|---|---|---|---|
| 1 | 1 | 11 | 6 | 1, 1, 2, 2 | 6 | 6 <= 8 可行，`hi = 6` |
| 2 | 1 | 6 | 3 | 1, 2, 3, 4 | 10 | 10 > 8 不可行，`lo = 4` |
| 3 | 4 | 6 | 5 | 1, 2, 2, 3 | 8 | 8 <= 8 可行，`hi = 5` |
| 4 | 4 | 5 | 4 | 1, 2, 2, 3 | 8 | 8 <= 8 可行，`hi = 4` |
| 結束 | 4 | 4 | — | — | — | `lo == hi`，回傳 `4` |

第 3、4 輪 `mid = 5` 和 `mid = 4` 剛好都是 8 小時：速度 5 雖然可行，但不是最小，`hi = mid` 讓搜尋繼續往左找，直到確認 `3` 不可行（第 2 輪已知）、`4` 可行，才停在 4。

第二個範例 `h = 5` 等於堆數，每堆都只能分到一小時，答案只能是 `max(piles) = 30`，二分會一路把 `lo` 往右推到 `hi`。

## 程式碼實作

```python
class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        # 速度至少 1（0 會除以零）；max(piles) 一定可行，因為 h >= len(piles)
        lo, hi = 1, max(piles)

        # lo < hi 搭配 hi = mid：區間收斂到單一值時，就是第一個可行的速度
        while lo < hi:
            mid = (lo + hi) // 2
            # (p + mid - 1) // mid 是整數版的 ceil(p / mid)，不經過浮點數
            hours = sum((p + mid - 1) // mid for p in piles)

            if hours <= h:
                # mid 可行，但左邊可能還有更小的可行速度，所以保留 mid
                hi = mid
            else:
                lo = mid + 1

        return lo
```

---

## 正確性說明

1. **不重複 (No Redundancy)**：`lo < hi` 時 `mid = (lo + hi) // 2` 嚴格小於 `hi`，所以 `hi = mid` 與 `lo = mid + 1` 都讓區間嚴格縮小，同一個速度不會被檢查兩次，迴圈也一定會結束。
2. **不遺漏 (Completeness)**：迴圈不變式是「最小可行速度一定在 `[lo, hi]` 內」。初始時成立，因為 `max(piles)` 可行、而速度小於 1 沒有意義。`mid` 可行時，由單調性知道答案 `<= mid`，保留 `[lo, mid]`；`mid` 不可行時，所有 `<= mid` 的速度也都不可行，捨棄它們是安全的。區間剩一個值時，它就是答案。
3. **邊界條件**：
   - 只有一堆：`piles = [p]`，答案是 `ceil(p / h)`，二分照樣收斂到它。
   - `h == len(piles)`：每堆只能一小時，答案就是 `max(piles)`，`lo` 會被推到 `hi`。
   - `h` 遠大於總根數（例如 `h = 10^9`）：答案是 1，`hi` 一路往左縮到 `lo = 1`。
   - 所有堆都是 1：`lo = hi = 1`，迴圈一次都不跑，直接回傳 1。

## 複雜度分析

- **Time Complexity**: $O(n \log M)$
  - 其中 $n$ 為堆數 `len(piles)`，$M$ 為 `max(piles)`。
  - 二分的搜尋範圍長度是 $M$，`lo < hi` 這套模板不會提早結束，迴圈次數幾乎固定是 $\lceil \log_2 M \rceil$ 左右；每輪要掃過全部 $n$ 堆算時數。
  - 最好與最壞情況差別不在迴圈次數，而在 $M$ 的大小：$M = 1$ 時迴圈不跑，只剩 `max(piles)` 的 $O(n)$；$M = 10^9$ 時約 30 輪，總共約 $30n$ 次除法。
- **Space Complexity**: $O(1)$
  - 只用幾個整數變數；`sum(... for p in piles)` 是 generator，不會建出長度 $n$ 的中間陣列。

## 常見誤區與補充

1. **兩套二分模板混用**：寫成 `while lo <= hi` 卻搭配 `hi = mid`，當 `lo == hi` 且該速度可行時，`hi = mid` 不會讓區間縮小，形成無窮迴圈。要嘛 `lo < hi` + `hi = mid` + 回傳 `lo`；要嘛 `lo <= hi` + `hi = mid - 1` + 另外用變數記錄答案，不能各取一半。
2. **`lo` 從 0 開始**：`lo = 0`、`hi = 1` 時 `mid = 0`，算時數時直接除以零。速度的合理下界是 1。
3. **以為一小時內吃完一堆還能接著吃下一堆**：那樣總時數會變成 `ceil(sum(piles) / k)`。對範例 `[30, 11, 23, 4, 20]`、`h = 6`，總和 88，`ceil(88 / 15) = 6` 會讓 `k = 15` 看起來可行，但實際每堆分開算是 `2 + 1 + 2 + 1 + 2 = 8` 小時，正確答案是 23。題目規定每小時只碰一堆，所以必須**每堆各自**向上取整再加總。
4. **把 `sum(piles) // h` 當答案**：這只是平均速度，忽略了每堆的零頭會浪費掉整整一小時。以 `[3, 6, 7, 11]`、`h = 8` 為例，`27 // 8 = 3`，但速度 3 需要 10 小時，不可行。它可以拿來當**下界**（見延伸思考），但不能當答案，也不能當上界。
5. **向上取整寫成 `p // mid + 1`**：`p` 剛好整除 `mid` 時會多算一小時，例如 `p = 6`、`mid = 3` 算出 3 而不是 2。用 `(p + mid - 1) // mid` 或 `-(-p // mid)`；Python 的 `math.ceil(p / mid)` 在本題的數值範圍內結果也正確，只是多了一次浮點轉換。
6. **補充：其他語言的溢位**：Python 整數不會溢位，但在 Java / C++ 裡，`k = 1` 時總時數最多是 $10^4 \times 10^9 = 10^{13}$，超出 32-bit `int`，`hours` 要宣告成 `long`；`(lo + hi) / 2` 在 `hi` 接近 $10^9$ 時加總也接近 int 上限，習慣寫成 `lo + (hi - lo) / 2`。

## 延伸思考

### 收緊搜尋範圍與提早結束
下界可以從 1 收緊到 $\lceil \text{sum}(piles) / h \rceil$：就算沒有零頭浪費，速度低於平均值也不可能在 `h` 小時內吃完。另外，算時數時一旦累加超過 `h` 就能直接判定不可行，不必掃完整個陣列：

```python
class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        # 平均速度是不可能再低的下界
        lo, hi = (sum(piles) + h - 1) // h, max(piles)

        while lo < hi:
            mid = (lo + hi) // 2
            hours = 0
            for p in piles:
                hours += (p + mid - 1) // mid
                # 已經超過 h，後面的堆不用再算
                if hours > h:
                    break

            if hours <= h:
                hi = mid
            else:
                lo = mid + 1

        return lo
```

這兩個最佳化都不改變 $O(n \log M)$ 的量級，只是常數變小：下界收緊讓迴圈少跑幾輪，early exit 讓不可行的 `mid` 提早結束那一輪。這也是複雜度分析裡「最好情況」真正會出現差異的地方。

### 「對答案二分」的辨識方式
題目問「**最小**的 X 使得某條件成立」或「**最大**的 X 使得某條件成立」，而且給定 X 後可以在線性時間內**驗證**條件，同時條件對 X 單調——這三點同時出現，就可以考慮對答案二分。本題的 X 是速度，驗證是算時數；1011. Capacity To Ship Packages Within D Days 的 X 是船的載重，驗證是模擬裝箱，結構完全一樣。

## 小結

這題是「對答案空間二分 (Binary Search on Answer)」的入門題：搜尋的不是陣列索引，而是可能的答案值，判斷式則是一個 $O(n)$ 的可行性檢查。

**核心觀念：**
- 先確認判斷式 `hours(k) <= h` 對 `k` 單調（F…F T…T），才有資格二分；要找的是第一個 `T`，屬於 lower bound 型。
- `lo < hi` + `hi = mid` + `lo = mid + 1` 是找第一個可行值的固定模板，範圍是 `[1, max(piles)]`。
- 每堆各自向上取整 `(p + k - 1) // k` 再加總，這是題意「一小時只碰一堆」的直接翻譯。
