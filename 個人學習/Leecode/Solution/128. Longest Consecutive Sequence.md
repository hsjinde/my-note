## 題目描述 (中文摘要)

給定一個**未排序**的整數陣列 `nums`，找出其中最長的「連續數字序列」的長度。所謂連續是指數值上連號（例如 `1,2,3,4`），**與元素在陣列中的位置無關**。

- 陣列可能為空，此時答案為 `0`。
- 元素可以重複、可以是負數；重複值不會讓序列變長。
- 題目要求時間複雜度必須是 $O(N)$，因此**不允許先排序再掃描**。

範例：

```
輸入：nums = [100, 4, 200, 1, 3, 2]
輸出：4
說明：最長連續序列是 [1, 2, 3, 4]，長度為 4。
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫

核心觀察：一段連續序列裡，只有**最小的那個數字**值得當起點往上數；其餘元素都會在那次計數中被走過，不需要重複展開。

1. **演算法選擇**：採用 **雜湊集合 + 起點判定 (Hash Set + Sequence Start Detection)**。
2. **具體步驟**：
   - 把所有數字丟進 `set`，讓「某個值是否存在」從 $O(N)$ 查詢降為 $O(1)$。
   - 遍歷集合中的每個數字 `n`，檢查 `n - 1` 是否存在：
     - 若存在 → `n` 是某段序列的中間段，直接跳過。
     - 若不存在 → `n` 是該段序列的起點，往上數 `n+1, n+2, ...` 直到斷掉。
   - **關鍵剪枝**：起點判定讓每段序列只被完整走一次，總工作量才維持在線性。

### English Interview Plan

Find the length of the longest run of consecutive integers in an unsorted array, in $O(N)$ time.

1. **Strategy**: Sorting would cost $O(N \log N)$, so instead trade space for time — build a hash set for $O(1)$ membership tests, then expand each run exactly once from its smallest element.
2. **Execution**:
   - **Setup**: `num_set = set(nums)`; the answer starts at `0`, which is also the correct result for an empty input.
   - **Iterative Step**: For each `n` in the set, treat it as a sequence start only if `n - 1` is absent. From a start, walk `n + 1, n + 2, ...` while each value is in the set, counting the length.
   - **Key Insight**: Every consecutive run has exactly one element with no predecessor in the set. Anchoring the walk on that element guarantees each value is visited by at most one expansion, so the nested `while` does **not** make this quadratic.

## 演算法詳解

暴力解會對每個數字都往上數一次，`[1,2,3,...,N]` 這種輸入下總步數是 $1 + 2 + \dots + N$，即 $O(N^2)$。先排序再掃描雖然正確，但 $O(N \log N)$ 不符題目要求。

本解法用**起點判定**同時解決這兩個問題：把「往上數」的權利只交給每段序列的最小值。判斷是不是最小值只需一次 $O(1)$ 的 `n - 1 in num_set`，成本極低，但省掉的是所有中間段的重複展開。

### 狀態變化 (State Transitions)

以 `nums = [100, 4, 200, 1, 3, 2]` 為例，`num_set = {1, 2, 3, 4, 100, 200}`。（`set` 的遍歷順序不保證，以下為方便說明採升序；因為每段序列只認自己的最小值當起點，無論以什麼順序遍歷，結果都一樣。）

1. **`n = 1`**：`0 not in num_set` → 是起點。往上數 `1, 2, 3, 4` 都在集合中，`5` 不在 → `length = 4`，`longest = 4`。
2. **`n = 2`**：`1 in num_set` → **直接跳過**（不進 while 迴圈）。
3. **`n = 3`**：`2 in num_set` → 跳過。
4. **`n = 4`**：`3 in num_set` → 跳過。
5. **`n = 100`**：`99 not in num_set` → 是起點。`101` 不在集合 → `length = 1`，`longest` 維持 `4`。
6. **`n = 200`**：`199 not in num_set` → 是起點。`201` 不在集合 → `length = 1`，`longest` 維持 `4`。
7. 最終回傳 `4`。

注意步驟 2–4：`2`、`3`、`4` 這三個元素**一次 while 迴圈都沒跑**，它們早在步驟 1 就被數過了。這正是總工作量停在 $O(N)$ 的原因——while 迴圈的總執行次數等於所有元素數量，而不是「元素數量 × 序列長度」。

## 程式碼實作

```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        # 轉成 set 有兩個目的：membership test 降到 O(1)，同時自動去重
        num_set = set(nums)
        longest = 0

        # 遍歷 num_set 而非 nums：重複值只需處理一次，
        # 否則同一個起點會被重複展開，最壞退化成 O(N^2)
        for n in num_set:
            # n-1 存在代表 n 是序列中間段，交給它的起點去數就好
            if n - 1 not in num_set:
                length = 0
                while n + length in num_set:
                    length += 1
                longest = max(longest, length)

        return longest
```

## 正確性說明

1. **不重複 (No Redundancy)**：while 迴圈只從「沒有前驅」的元素展開。任一元素 `x` 只會被它所屬那段序列的最小值走到一次——因為若 `x` 被兩個不同起點走到，代表這兩個起點在同一段連續區間內，而一段連續區間只有一個最小值，矛盾。
2. **不遺漏 (Completeness)**：把整數集合切成極大連續區間，每個區間恰有一個元素 `x` 滿足 `x - 1 ∉ num_set`（即該區間的最小值）。迴圈遍歷了集合中所有元素，因此每個區間都恰好被完整計算一次，最長者必被 `max` 取到。
3. **邊界條件**：
   - **空陣列**：`num_set` 為空，for 迴圈不執行，直接回傳初始值 `0`。
   - **單一元素**：`n - 1` 必不存在 → 是起點，while 跑一輪得 `length = 1`。
   - **全部相同值**（如 `[5,5,5,5]`）：`set` 去重後只剩 `{5}`，答案為 `1`。
   - **含負數 / 跨零**（如 `[-1, 0, 1]`）：邏輯只依賴數值加減，不依賴正負，答案為 `3`。

## 複雜度分析

- **Time Complexity**: $O(N)$
  - 其中 $N$ 為 `nums` 的元素個數。建立 `set` 為 $O(N)$；外層迴圈執行至多 $N$ 次，每次做一個 $O(1)$ 的起點判定；內層 while 的**總**執行次數等於所有元素被走過的次數，由「不重複」性質可知恰為 $O(N)$。
  - 最好情況（全部元素互不相鄰，如 `[1, 3, 5, 7]`）與最壞情況（全部連號，如 `[1, 2, ..., N]`）都是 $O(N)$——差別只在工作量落在外層還是內層，總和不變。
- **Space Complexity**: $O(N)$
  - 額外空間來自 `num_set`。最壞情況（無重複值）需存下全部 $N$ 個元素；若輸入重複度高，實際佔用會小於 $N$，但漸進上限仍是 $O(N)$。

## 常見誤區

1. **遍歷 `nums` 而不是 `num_set`，讓複雜度悄悄退化**：寫成 `for n in nums:` 邏輯上答案仍正確，但重複值會讓同一個起點被展開多次。以 `nums = [1]*5000 + [2, 3, ..., 5000]` 為例，五千個 `1` 都通過 `0 not in num_set` 的檢查，各自跑滿長度五千的 while 迴圈 → 約 $N^2/4$ 次操作，實際是 $O(N^2)$。改成遍歷去重後的 `num_set` 即可修掉，演算法本身完全不用動。
2. **省略 `n - 1 not in num_set` 的起點判定**：只要把這個 if 拿掉，就退化成「每個元素都往上數一次」的暴力解，`[1,2,...,N]` 下是 $O(N^2)$。這一行不是可有可無的優化，它是整個 $O(N)$ 的支點。
3. **先排序再掃描**：`sorted(nums)` 後線性掃描（記得跳過重複值）雖然能過測資，但時間是 $O(N \log N)$，直接違反題目明訂的 $O(N)$ 要求，面試時會被追問。
4. **用 list 而非 set 做 membership test**：若寫成 `if n - 1 not in nums:`（`nums` 是 list），每次查詢是 $O(N)$，整體變成 $O(N^2)$ 起跳。這題的線性複雜度完全建立在雜湊查詢是 $O(1)$ 之上。
5. **把 `longest = max(longest, length)` 移出 if 區塊**：直覺上以為「每輪都更新比較保險」，實際上非起點的那些 `n` 會拿上一輪殘留的 `length` 去比較。因為殘留值早已被併入 `longest`，答案本身不會錯，但只要 `num_set` 第一個走到的元素不是起點，`length` 就還沒被綁定，直接 `UnboundLocalError`——而 `set` 的遍歷順序不保證，同一份程式碼可能今天過、明天炸。正確寫法是把更新留在 if 之內，且 `length` 必須在每次進入 if 時重新歸零，否則會沿用上一段序列的長度繼續累加。

## 延伸思考

- **並查集 (Union-Find) 解法**：把每個數字視為節點，若 `n` 與 `n + 1` 同時存在就 union 起來，最後取最大集合的 size。時間複雜度為 $O(N \cdot \alpha(N))$（$\alpha$ 為反阿克曼函數，實務上可視為常數），漸進上與雜湊解法同級，但常數更大、程式碼更長。適合當作「知道還有這條路」的備案，面試時仍建議先講 hash set 解法。
- **排序解法為何仍值得會**：若面試官把限制放寬（例如記憶體極度受限、不允許 $O(N)$ 額外空間），in-place 排序後線性掃描的 $O(N \log N)$ 時間 / $O(1)$ 額外空間反而是更好的權衡。能說出這個 trade-off 比只會背最優解更有說服力。
- **變形：回傳序列本身而非長度**：只要在更新 `longest` 時一併記下起點 `n`，最後用 `range(start, start + longest)` 還原即可，不影響複雜度。

## 小結

這題屬於**用雜湊集合換取線性時間**的經典題型：表面上有巢狀迴圈，實際靠「每段只從起點展開一次」的攤還分析 (Amortized Analysis) 壓在 $O(N)$。

**核心觀念：**
- 看到「要求 $O(N)$」且題目與順序無關時，第一反應應該是 hash set，而不是排序。
- 巢狀迴圈不等於 $O(N^2)$——關鍵是內層迴圈的**總**執行次數，而不是單次最壞長度。
- 去重不只是為了正確性，有時（如本題）它直接決定了複雜度是否成立。
