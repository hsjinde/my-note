## 題目描述 (中文摘要)
給定只含大寫英文字母的字串 `s` 與整數 `k`，最多可以把 `k` 個字元換成任意大寫字母。
回傳操作後「全部由同一字母組成」的最長子字串長度。

限制：`1 <= s.length <= 10^5`，`0 <= k <= s.length`。

範例：
```
輸入：s = "AABABBA", k = 1
輸出：4
說明：把 index 3 的 'A' 換成 'B'（或把 index 2 的 'B' 換成 'A'），可得長度 4 的 "BBBB" / "AAAA"。
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
核心觀察：一個視窗要全部變成同一字母，最少需要的替換次數 = `視窗長度 - 視窗內出現最多次的字母數`。只要這個值 `<= k`，視窗就合法。
1. **演算法選擇**：採用 **滑動視窗 (Sliding Window)** 搭配字母計數。
2. **具體步驟**：
   - 右指標逐一納入字元，更新該字母計數與 `longestCount`（視窗內最高頻次數）。
   - 若 `視窗長度 - longestCount > k`，視窗不合法，左邊界右移一格。
   - 關鍵：`longestCount` 只增不減。答案只有在出現更高的頻次時才可能變大，所以舊的較大值不會讓答案出錯。

### English Interview Plan
Find the longest substring that can be made uniform with at most `k` replacements.
1. **Strategy**: Sliding window with a letter-frequency counter, O(N) time and O(1) space (26 letters).
2. **Execution**:
   - **Base Case**: Empty window, all counts zero, answer zero.
   - **Iterative Step**: Extend the right end; if `window_len - max_freq > k`, slide the left end forward by one.
   - **Key Insight**: `max_freq` never needs to be decreased. The answer can only grow when a strictly higher frequency appears, so a stale (historical) maximum never produces a wrong result; it only keeps the window from shrinking.

## 演算法詳解

暴力解會列舉所有子字串 $O(N^2)$，每個再算最高頻次，總共 $O(N^2)$ 以上。
滑動視窗利用「合法視窗往左縮仍合法」的單調性，讓左右指標都只往右走，壓到 $O(N)$。

原始版本更進一步：視窗長度 `maxlen` 只增不縮。不合法時左右邊界「一起右移一格」，視窗長度維持不變，等於帶著目前最佳長度往右平移，找有沒有更長的合法視窗。

### 狀態變化 (State Transitions)
以 `s = "AABABBA", k = 1` 為例。判斷式 `maxlen - longestCount >= k` 是在 `maxlen` 加一之前檢查，等價於 `(maxlen + 1) - longestCount > k`（納入新字元後的視窗不合法）。

| i | 新字元 | 判斷前 Counter | longestCount | `maxlen - longestCount >= k`？ | 動作 | maxlen | 視窗 |
|:-:|:-:|:--|:-:|:--|:--|:-:|:--|
| 0 | A | `{A:1}` | 1 | 0-1=-1，否 | 擴張 | 1 | `A` |
| 1 | A | `{A:2}` | 2 | 1-2=-1，否 | 擴張 | 2 | `AA` |
| 2 | B | `{A:2, B:1}` | 2 | 2-2=0，否 | 擴張 | 3 | `AAB` |
| 3 | A | `{A:3, B:1}` | 3 | 3-3=0，否 | 擴張 | 4 | `AABA` |
| 4 | B | `{A:3, B:2}` | 3 | 4-3=1，是 | 移出 `s[0]='A'` → `{A:2, B:2}` | 4 | `ABAB` |
| 5 | B | `{A:2, B:3}` | 3 | 4-3=1，是 | 移出 `s[1]='A'` → `{A:1, B:3}` | 4 | `BABB` |
| 6 | A | `{A:2, B:3}` | 3 | 4-3=1，是 | 移出 `s[2]='B'` → `{A:2, B:2}` | 4 | `ABBA` |

最終 `maxlen = 4`。注意最後的視窗 `ABBA` 需要替換 2 次，本身**不合法**。`maxlen` 記的是「曾經達到過的最長合法長度」，不代表最後那個視窗合法。

## 程式碼實作

### 原始版本 (視窗只增不縮)

```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        # maxlen 同時是「視窗長度」與「答案」：視窗只平移不縮小
        maxlen, longestCount = 0, 0
        hashmap = collections.Counter()
        for i in range(len(s)):
            hashmap[s[i]] += 1
            # 只增不減：歷史最高頻次夠用，因為答案只會在頻次創新高時變大
            longestCount = max(longestCount, hashmap[s[i]])
            # 在 maxlen 加一前判斷，等價於「納入 s[i] 後替換數 > k」
            if maxlen - longestCount >= k:
                # 視窗長度維持 maxlen，左邊界跟著右移一格
                hashmap[s[i - maxlen]] -= 1
            else:
                maxlen += 1
        return maxlen
```

### 標準版本 (while 收縮)

面試時較好解釋的寫法：左右指標明確、視窗在每一步都合法（以 `maxFreq` 為準）。

```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}
        left = 0
        maxFreq = 0
        best = 0
        for right, ch in enumerate(s):
            count[ch] = count.get(ch, 0) + 1
            maxFreq = max(maxFreq, count[ch])
            # 需要替換的字元數超過 k，就從左邊縮到合法為止
            while (right - left + 1) - maxFreq > k:
                count[s[left]] -= 1
                left += 1
            best = max(best, right - left + 1)
        return best
```

兩個版本在隨機測資上與暴力解結果一致。由於 `maxFreq` 只增不減，`while` 實際上最多執行一次，行為和原始版本相同。

## 正確性說明

1. **不重複 (No Redundancy)**：左右指標都只往右移，每個字元最多被加入計數一次、移出一次，不會重複處理同一段子字串。
2. **不遺漏 (Completeness)**：
   - 設最佳解是以 `r` 結尾、最高頻次為 `f` 的視窗，長度 `L = f + k`（或受字串長度限制）。
   - 右指標走到 `r` 時，`longestCount >= f`，因此演算法允許的視窗長度至少是 `L`，答案不會被低估。
   - 反過來，`maxlen` 只在 `(maxlen + 1) - longestCount <= k` 時增加。這時 `longestCount` 等於某個真實出現過的頻次，而取得該頻次的那個視窗長度正好是 `maxlen + 1`、替換數 `<= k`，確實合法，答案也不會被高估。
3. **邊界條件**：
   - `k = 0`：退化成「最長連續相同字元」，判斷式變成 `maxlen - longestCount >= 0`，只有同字母連續時才會擴張。
   - `k >= len(s)`：任何視窗都合法，答案為 `len(s)`。
   - 全同字元，例如 `"AAAA"`：`longestCount` 始終等於 `maxlen + 1`，每步都擴張，答案為 `len(s)`。
   - 單一字元：答案為 1。

## 複雜度分析

- **Time Complexity**: $O(N)$
  - 其中 $N$ 為 `s` 的長度。每個字元只進出視窗各一次，每步只做 $O(1)$ 的計數與比較。最好、最壞情況都是 $O(N)$。
  - 如果每步都用 `max(count.values())` 重算最高頻次，會變成 $O(26N)$，量級不變但常數大了 26 倍。
- **Space Complexity**: $O(1)$
  - 計數表最多 26 個鍵（大寫英文字母），跟 $N$ 無關。若字元集改成一般字元集 $\Sigma$，則為 $O(|\Sigma|)$。

## 常見誤區

1. **以為 `longestCount` 沒有在縮窗時遞減是 bug**：視窗移出字元後，真實的最高頻次可能下降，但 `longestCount` 刻意不更新。舊的較大值只會讓視窗「不縮」，不會讓 `maxlen` 錯誤增加。因為 `maxlen` 要變大，必須等到出現更高的頻次。硬要每步重算反而多花 26 倍時間。
2. **把最後的視窗當成答案字串**：原始版本的視窗只平移不縮小，結尾視窗可能不合法（上面 trace 的 `ABBA` 就需要 2 次替換）。`maxlen` 只代表長度，若題目改成「回傳子字串本身」，要在 `maxlen` 增加時另外記下位置。
3. **判斷式差一 (off-by-one)**：`maxlen - longestCount >= k` 是在納入新字元、但 `maxlen` 還沒加一時檢查的，等價於 `新長度 - longestCount > k`。若誤寫成 `> k`，會讓需要 `k + 1` 次替換的視窗通過，答案偏大；例如 `s = "ABAB", k = 0` 會回傳 3 而非 1；`s = "AABABBA", k = 1` 會回傳 5 而非 4。
4. **只盯著一個目標字母**：另一種做法是先固定「要全部變成字母 `c`」，視窗條件改看 `c` 的頻次。這樣寫也對，但必須對 26 個字母各跑一次；只跑某一個字母（例如 `s[0]`）就會漏掉答案。改用「視窗內最高頻次」可以一次處理所有字母。
5. **`collections.Counter` 沒有 import 就直接貼到本機跑**：LeetCode 環境預先匯入了 `collections`，本機測試要自己加 `import collections`，不然會 `NameError`。

## 小結

這題是「可變長度滑動視窗 + 計數」的代表題，重點在把「最多替換 k 次」轉成 `視窗長度 - 最高頻次 <= k` 這個可以 $O(1)$ 檢查的條件。

**核心觀念：**
- 合法條件：`window_len - max_freq <= k`。
- 求「最大」視窗時，視窗可以只平移不縮小；`max_freq` 只增不減也不影響答案。
- 左右指標都單向移動，所以是 $O(N)$。
