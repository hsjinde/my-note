# Skill: leetcode-note

產出符合本 vault 房規的 LeetCode 解題說明文件。風格來源是 `個人學習/Leecode/Solution/` 內的
`110. Balanced Binary Tree.md`、`572. Subtree of Another Tree.md`（骨幹）與
`2596. Check Knight Tour Configuration.md`、`1905. Count Sub Islands.md`（選配段落）。

**以本 SKILL.md 與 `references/template.md` 為準，不要逐字照抄既有筆記**——它們是這套規範收斂之前的產物，彼此並不一致：
`110`／`572` 用舊的 `## 標題與目錄` 結構、`110` 檔尾殘留一句對話式提問、`572` 的 `class Solution:` 在 code fence 內整段縮排四格（貼進 LeetCode 會壞）、
`1905`／`2596` 的思路總覽只有中文沒有 English Interview Plan。這些都是本 skill 要修掉的問題。

## 產出位置與檔名

- 目錄：`個人學習/Leecode/Solution/`
- 檔名：`<題號>. <English Title>.md`，可選中文副標 → `121. Best Time to Buy and Sell Stock (買賣股票的最佳時機).md`
- **檔名衝突 → 停下來問使用者**，絕不自行加 `(1)`。
  （曾有一份 `110. Balanced Binary Tree (1).md` 內容其實是 543 的筆記，就是這樣造成的錯置，已更名修正。）
- `個人學習/` 屬原始區：本 skill **只新增檔案**。要覆寫或大改既有筆記前，先取得使用者確認。

## 執行流程

1. **確認輸入**：題號、英文標題、使用者的解法（程式碼或口述）。缺程式碼就先問要用哪個解法，不要自己選一個冷門解法硬寫。
   若對題目敘述、輸入輸出格式或限制條件沒有把握，**先請使用者貼上題目原文或確認摘要**，不要憑印象寫。
2. **檢查同名檔**：`ls '個人學習/Leecode/Solution/' | grep '^<題號>\.'`，有就依上面的衝突規則處理。
3. **決定選配段落**：見下方「段落清單」。
4. **依 `references/template.md` 骨架撰寫**，目錄區塊直接複製範本（anchor 已算好）。
5. **自我檢查**：跑過下方「完成前檢查表」再回報。

## 段落清單

必備（骨幹，順序固定）：

| 段落 | 重點 |
|---|---|
| `# LeetCode <題號>. <English Title>` + 中文副標 | 副標另起一行，不塞進 H1 |
| `## 目錄` | 錨點連結，見格式規則 |
| `## 題目描述 (中文摘要)` | 3–6 行講清楚輸入、輸出、限制；grid/樹類題附一個小範例 |
| `## 思路總覽 (Overview & Interview Plan)` | **固定中英雙語**：中文解題計畫 + English Interview Plan |
| `## 演算法詳解` | 必須帶一次具體 trace（小輸入走一遍狀態變化），不能只重述思路 |
| `## 程式碼實作` | Python 為主，註解寫「為什麼」而非「這行在做什麼」 |
| `## 正確性說明` | 固定三點：不重複、不遺漏、邊界條件 |
| `## 複雜度分析` | 時間 + 空間，說明 N/H 各代表什麼、最好與最壞情況 |
| `## 常見誤區` | 至少 3 條，寫真的會踩的坑（含使用者原本寫法的問題） |
| `## 小結` | 核心觀念 2–3 條 + 推薦延伸練習（列 LeetCode 題號與標題） |

選配（有需要才加，加了就要同步進目錄）：

- 有多個解法 → `## 程式碼實作` 下用 `### <版本名>` 分節，目錄縮排列出子項。
- 複雜度分析超過 6 行或版本間複雜度不同 → 拆成 `## 時間複雜度分析` 與 `## 空間複雜度分析`。
- 有進階變形、最佳化方向或相關題型演進 → `## 延伸思考`（放在常見誤區之後、小結之前）。
- 誤區之外還要補背景知識 → 段落改名 `## 常見誤區與補充`。

## 格式規則

- **目錄錨點**：GitHub 規則 —— 轉小寫、刪除 `.` `(` `)` `&` `:` 等標點、剩下的空白換 `-`。
  例：`## 思路總覽 (Overview & Interview Plan)` → `#思路總覽-overview--interview-plan`（`&` 刪掉後留兩個空白，故為雙連字號）。
  常用段落的錨點已寫在 `references/template.md`，直接複製，不要現算。
- **程式碼**：code fence 的語言標籤就寫 `python`（純標籤），**不要**加 `!` 或 `=` 後綴（那是舊筆記的殘留寫法）。
- **數學**：行內 LaTeX，`$O(N)$`、`$O(\log N)$`、`$O(N^2)$`。
- **分隔線**：主要段落之間用 `---`（骨幹版本有用，選配段落也比照）。
- **語言**：繁體中文為主，演算法術語保留英文並在首次出現時中英並列，如「後序遍歷 (Post-order Traversal)」。
- **結尾**：文件在 `## 小結` 結束。**禁止**任何對話尾巴，例如「Would you like me to…」「需要我再補充嗎？」——`110. Balanced Binary Tree.md` 就殘留了這種句子，別複製它。
- 不加 frontmatter、不加 emoji（既有筆記都沒有）。

## 完成前檢查表

- [ ] 目錄每個連結都對得上實際的 `##` 標題（含選配段落）
- [ ] code fence 語言標籤是純 `python`（無 `!` / `=`），且程式碼從第 0 欄開始、可直接貼進 LeetCode 執行
- [ ] 複雜度有寫清楚符號定義與最好/最壞情況
- [ ] 常見誤區 ≥ 3 條且具體（不是「要注意邊界」這種廢話）
- [ ] 小結有列延伸練習題號
- [ ] 檔尾沒有對話語句、沒有 TODO、沒有未填的佔位符
- [ ] 檔名符合 `<題號>. <English Title>.md`，且沒有覆蓋到既有檔案

## 常見錯誤

| 錯誤 | 修正 |
|---|---|
| 目錄錨點少算 `&` 造成的雙連字號 | 複製 `references/template.md` 的目錄區塊 |
| 演算法詳解只是把思路總覽換句話說 | 補一次具體輸入的逐步 trace |
| 只寫「時間 $O(N)$」不說 N 是什麼 | 明確定義符號並給最好/最壞情況 |
| 把 `## 小結` 之後又補一句問句 | 刪掉，文件到小結為止 |
| 同題號檔案已存在就存成 `(1)` | 停下來問使用者要更新哪一份 |
| 憑印象寫題目描述，寫錯限制條件 | 不確定就先跟使用者要題目原文 |
