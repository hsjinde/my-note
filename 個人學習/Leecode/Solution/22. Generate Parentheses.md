## 題目描述 (中文摘要)
給定整數 `n`，代表有 `n` 對括號，請產生**所有**由這 `n` 對括號組成、且格式正確（有效）的括號字串，回傳順序不限。

「有效」的定義與 20. Valid Parentheses 相同：每個 `(` 都要被後面的某個 `)` 關閉，且任何前綴中 `)` 的數量都不能超過 `(`。

限制：`1 <= n <= 8`。

範例：
```
輸入：n = 3
輸出：["((()))","(()())","(())()","()(())","()()()"]

輸入：n = 1
輸出：["()"]
```

---

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫
核心觀察：**一個前綴能不能繼續長成有效字串，只取決於「已經放了幾個 `(`」和「已經放了幾個 `)`」這兩個數字**，所以不必先生成再驗證，可以邊生成邊剪枝。
1. **演算法選擇**：採用 **回溯法 (Backtracking)**，以兩個計數器 `openN`、`closedN` 作為剪枝條件，並用一個共用的 `stack` 記錄目前的路徑。
2. **具體步驟**：
   - 從空字串開始，每一步決定要放 `(` 還是 `)`。
   - 只要 `openN < n`，就可以再放一個 `(`。
   - 只有在 `closedN < openN` 時才能放 `)`——代表目前還有開著、沒被關閉的 `(`。
   - 當 `openN == closedN == n` 時，路徑長度剛好是 `2n` 且必定有效，把它加入答案。
   - 每次遞迴回來後 `pop` 掉剛剛放的字元，把共用路徑還原，再嘗試另一個分支。

### English Interview Plan
The goal is to enumerate every well-formed string made of `n` pairs of parentheses.
1. **Strategy**: Backtracking with two counters. Instead of generating all $2^{2n}$ strings and filtering, only extend a prefix in ways that keep it valid, so every branch of the search ends in a real answer.
2. **Execution**:
   - **Base Case**: When `openN == closedN == n`, join the current path and record it.
   - **Recursive Step**: Add `(` if `openN < n`; add `)` if `closedN < openN`. Push before recursing and pop after returning.
   - **Key Insight**: The condition `closedN < openN` is exactly the "no prefix has more `)` than `(`" rule, so validity is enforced during construction and no separate check is needed.

## 演算法詳解

最直接的暴力解是：把長度 `2n` 的所有 `(` / `)` 組合都列出來（共 $2^{2n}$ 種），每一個再用 20 題的方法掃一遍檢查是否有效，總共是 $O(2^{2n} \cdot n)$。問題在於絕大多數組合一開始就注定無效——例如以 `)` 開頭的字串佔了一半，卻要等到整串生完才被丟掉。

回溯法把「有效」拆成兩條在**每一步**都能檢查的局部規則：

- `(` 的總數不能超過 `n` → 放 `(` 的條件是 `openN < n`。
- 任何前綴中 `)` 不能多於 `(` → 放 `)` 的條件是 `closedN < openN`。

只要每一步都守住這兩條，走到長度 `2n` 時字串就一定有效。更重要的是：**守住這兩條的前綴，一定能補完成一個有效字串**（把剩下的 `(` 全放完、再補上所有 `)` 即可），所以整棵搜尋樹裡沒有死路，每一條分支最後都對應到一個答案。

### 狀態變化 (State Transitions)
以 `n = 2` 為例，`stack` 是目前路徑，`(o, c)` 代表 `(openN, closedN)`：

| 步驟 | 動作 | `stack` | `(o, c)` | 說明 |
|---|---|---|---|---|
| 1 | 放 `(` | `(` | (1, 0) | `o < 2`，可以放 |
| 2 | 放 `(` | `((` | (2, 0) | `o < 2`，可以放 |
| 3 | 放 `)` | `(()` | (2, 1) | `o` 已滿；`c < o` 才能放 `)` |
| 4 | 放 `)` | `(())` | (2, 2) | 到達終點，記錄 `"(())"` |
| 5 | pop ×3 回到步驟 1 | `(` | (1, 0) | 步驟 2 的 `(` 分支已走完，改試 `)` |
| 6 | 放 `)` | `()` | (1, 1) | `c < o`，可以放 |
| 7 | 放 `(` | `()(` | (2, 1) | `o < 2`，可以放；此時 `c == o`，`)` 分支被剪掉 |
| 8 | 放 `)` | `()()` | (2, 2) | 記錄 `"()()"` |
| 9 | pop 回到空路徑 | （空） | (0, 0) | 根節點想放 `)`，但 `c < o` 即 `0 < 0` 不成立，剪枝，結束 |

最終答案為 `["(())", "()()"]`。注意步驟 7 與步驟 9：`closedN < openN` 這條規則把 `())...` 和 `)...` 這些注定無效的前綴，在第一個字元就擋掉了。

## 程式碼實作

```python
class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        # 共用一個 list 當路徑，靠 append / pop 還原狀態，避免每層都複製字串
        stack = []
        res = []

        def backtrack(openN, closedN):
            # 兩種括號都用完，而且一路都守住 closedN <= openN，所以這條路徑必定有效
            if openN == closedN == n:
                res.append("".join(stack))
                return

            # ( 只受總數 n 限制
            if openN < n:
                stack.append("(")
                backtrack(openN + 1, closedN)
                stack.pop()

            # ) 必須有「還開著的 (」可以關，否則前綴就已經無效
            if closedN < openN:
                stack.append(")")
                backtrack(openN, closedN + 1)
                stack.pop()

        backtrack(0, 0)
        return res
```

## 正確性說明

1. **不重複 (No Redundancy)**：搜尋樹的每個節點代表一個唯一的前綴，每個節點最多分出 `(` 與 `)` 兩個子節點，兩條分支的下一個字元不同，所以從根走到葉的路徑兩兩相異，每個答案只會被記錄一次。
2. **不遺漏 (Completeness)**：任何有效字串的每一個前綴都滿足 `openN <= n` 且 `closedN <= openN`，因此它的每一步都不會被剪枝條件擋下——沿著這個字串的字元走，必定能從根走到對應的葉節點。反過來，被記錄的字串都滿足兩條規則且長度為 `2n`，必定有效。
3. **邊界條件**：
   - `n = 1`：只有 `(` → `)` 一條路，回傳 `["()"]`。
   - 根節點：`openN == closedN == 0`，`)` 分支被 `0 < 0` 擋掉，所以答案不會以 `)` 開頭。
   - `openN == n` 之後：`(` 分支全部關閉，只能一路補 `)` 直到 `closedN == n`，對應範例中 `((()))` 這種「先開滿再全關」的形狀。

## 複雜度分析

有效括號字串的數量是第 `n` 個卡特蘭數 (Catalan Number)：$C_n = \frac{1}{n+1}\binom{2n}{n}$，漸近量級為 $\frac{4^n}{n\sqrt{n}}$（例如 $C_3 = 5$、$C_8 = 1430$）。

- **Time Complexity**: $O\left(\frac{4^n}{\sqrt{n}}\right)$
  - 其中 $n$ 為括號對數。共有 $C_n$ 個答案，每個答案在終點要花 $O(n)$ 做 `"".join`，合計 $O(n \cdot C_n) = O\left(\frac{4^n}{\sqrt{n}}\right)$。
  - 搜尋樹的節點數：因為沒有死路，每個節點都是某個答案的前綴，而每個答案只有 $2n$ 個前綴，所以節點數不超過 $2n \cdot C_n$，量級相同。
  - 最好與最壞情況：對固定的 `n`，不論怎麼走都會把整棵樹走完、產生全部 $C_n$ 個答案，**沒有最好／最壞之分**；成本只隨 `n` 成長。
- **Space Complexity**: $O(n)$（不含輸出）
  - 遞迴深度最多 $2n$ 層，`stack` 長度最多 $2n$，皆為 $O(n)$。
  - 若把輸出算進去，`res` 存了 $C_n$ 個長度 $2n$ 的字串，為 $O(n \cdot C_n)$。

## 常見誤區

1. **放 `)` 的條件寫成 `closedN < n`**：這只限制了 `)` 的總數，沒有限制順序，會產生 `")("`、`"())("` 這類前綴就已經無效的字串。正確條件是 `closedN < openN`，它才代表「目前有開著的 `(` 可以關」。
2. **遞迴回來後忘了 `stack.pop()`**：共用的 `stack` 不會自己還原，少了 `pop` 時，`(` 分支留下的字元會殘留到 `)` 分支。以 `n = 2` 為例，走完 `(())` 回到步驟 5 時 `stack` 仍是 `["(", "(", ")", ")"]`，之後的結果全部錯位。
3. **終點寫成 `res.append(stack)`**：加進去的是 `stack` 這個 list 的**參考**，之後的 `pop` 會一路把它清空，最後 `res` 裡全是同一個空 list。必須用 `"".join(stack)` 在當下產生一個新字串。
4. **終點只檢查 `openN == n`**：此時 `)` 可能還沒補完，例如 `n = 2` 時 `"(("` 就會被提早記錄。要用 `openN == closedN == n`，或等價的 `len(stack) == 2 * n`。
5. **以為這題要用堆疊做括號配對**：NeetCode 把它放在 Stack 分類，但這裡的 `stack` 只是回溯的「路徑」，真正保證有效的是兩個計數器。如果在生成過程中還去模擬 20 題的配對堆疊，只是多做一份計數器已經做完的事。

## 延伸思考

- **改用字串傳參，省掉 `pop`**：寫成 `backtrack(cur + "(", openN + 1, closedN)`，每層都會產生新字串，回來時舊的 `cur` 沒被動到，所以不需要手動還原。代價是每次呼叫都要 $O(n)$ 複製字串，但在 `n <= 8` 下差異可以忽略，寫起來比較不容易漏 `pop`。
- **動態規劃 (Dynamic Programming) 的拆法**：任何有效字串都可以唯一寫成 `"(" + A + ")" + B`，其中 `A` 是包在第一個 `(` 裡面的有效字串（`i` 對），`B` 是後面接著的有效字串（`n - 1 - i` 對）。由 `dp[0] = [""]` 往上組合即可得到 `dp[n]`。這正是卡特蘭數遞迴式 $C_n = \sum_{i=0}^{n-1} C_i \cdot C_{n-1-i}$ 的來源。
- **同一套剪枝思路的其他題**：「只用計數器就能判斷前綴是否還有救」這個觀念，在 678. Valid Parenthesis String 中變成追蹤 `openN` 的可能範圍，在 301. Remove Invalid Parentheses 中則用來決定要刪掉哪些多餘的括號。

## 小結

這題是回溯法 (Backtracking) 的經典入門題：在生成過程中用局部規則剪枝，讓搜尋只走在合法的解空間裡。

**核心觀念：**
- 括號字串是否有效，可以拆成兩條每一步都能檢查的計數規則：`openN <= n`、`closedN <= openN`。
- 剪枝做對了，搜尋樹就沒有死路，總工作量與答案數量（卡特蘭數）同一個量級。
- 共用路徑的回溯一定是「append → 遞迴 → pop」成對出現，記錄答案時要複製出新的字串。
