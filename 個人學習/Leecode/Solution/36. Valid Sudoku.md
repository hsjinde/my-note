## 題目描述 (中文摘要)

給定一個 9x9 的數獨盤面 `board`，判斷「目前已填入的部分」是否合法，回傳 `True` / `False`。合法的定義有三條：每一列 (row) 的數字不重複、每一行 (column) 的數字不重複、每一個 3x3 宮格 (box) 的數字不重複。

兩個容易寫錯的限制：

- `board[i][j]` 是**字串** (`str`)，內容為 `'1'`–`'9'` 或代表空格的 `'.'`，不是整數。
- 盤面**可以只填一部分**，而且**不需要保證這個盤面最終有解**。只要已填的數字沒有互相衝突就算合法。

範例：

```
輸入（只看左上角這個 3x3 宮格）：
5 3 .
6 . .
. 9 8

輸出：這個宮格內 {5, 3, 6, 9, 8} 皆不重複 → 合法
若把最後一格的 8 改成 5，宮格內出現兩個 5 → 不合法
```

## 思路總覽 (Overview & Interview Plan)

### 中文解題計畫

核心觀察：列、行、宮格這三種約束彼此獨立，可以在同一次掃描中用三組獨立的記錄同時檢查，不必分三輪掃盤。

1. **演算法選擇**：採用 **一次掃描搭配雜湊集合 (One-pass with Hash Sets)**。
2. **具體步驟**：
   - 準備三組長度為 9 的 `set`：`rows`、`cols`、`boxes`，分別記錄第 `r` 列、第 `c` 行、第 `b` 個宮格已經出現過哪些數字。
   - 依序走訪 81 個格子；遇到 `'.'` 直接跳過，因為空格不構成任何衝突。
   - 用 `b = (r // 3) * 3 + c // 3` 把座標 `(r, c)` 映射到 0–8 的宮格編號。
   - 若目前數字已存在於 `rows[r]`、`cols[c]`、`boxes[b]` 任何一個，立刻回傳 `False`；否則同時寫入三個集合。
   - 全部走訪完畢沒有衝突就回傳 `True`。

### English Interview Plan

Determine whether the currently filled cells of a 9x9 Sudoku board violate any row, column, or 3x3 box constraint.

1. **Strategy**: Because the three constraints are independent, one pass over all 81 cells with three arrays of hash sets validates all of them simultaneously — no need for three separate sweeps.
2. **Execution**:
   - **Base Case**: A `'.'` cell carries no digit, so it is skipped and never recorded.
   - **Iterative Step**: For each filled cell `(r, c)`, compute the box id `b = (r // 3) * 3 + c // 3`. If the digit already appears in `rows[r]`, `cols[c]`, or `boxes[b]`, return `False` immediately; otherwise insert it into all three sets.
   - **Key Insight**: Multiplying `r // 3` by 3 is what makes the box id injective — it lays the 9 boxes out in row-major order as a flat 0–8 index.

## 演算法詳解

先看為什麼不用「暴力比對」。若對每個格子都去掃描它所屬的整列、整行、整宮，每格要比對約 27 次，程式碼還會分裂成三段幾乎相同的迴圈；一旦其中一段的索引寫錯（尤其是宮格那段），錯誤非常難察覺。改用集合後，「是否重複」變成 $O(1)$ 的查表，三種約束的檢查邏輯也被壓成同一段程式。

宮格編號的映射是本題唯一的關鍵計算：

```
b = (r // 3) * 3 + c // 3

(r//3, c//3) = (0,0) → b = 0    (0,1) → b = 1    (0,2) → b = 2
               (1,0) → b = 3    (1,1) → b = 4    (1,2) → b = 5
               (2,0) → b = 6    (2,1) → b = 7    (2,2) → b = 8
```

### 狀態變化 (State Transitions)

以左上角這個 3x3 區塊為例（其餘格子皆為 `'.'`），觀察掃描過程中三組集合的變化：

```
5 3 .
6 . .
. 9 5
```

1. `(r, c) = (0, 0)`，`val = '5'`，`b = (0//3)*3 + 0//3 = 0`。三個集合都是空的 → 寫入。
   此時 `rows[0] = {'5'}`、`cols[0] = {'5'}`、`boxes[0] = {'5'}`。
2. `(0, 1)`，`val = '3'`，`b = 0`。`'3'` 不在 `rows[0]`、`cols[1]`、`boxes[0]` 中 → 寫入。
   此時 `rows[0] = {'5','3'}`、`cols[1] = {'3'}`、`boxes[0] = {'5','3'}`。
3. `(0, 2)`，`val = '.'` → `continue`，三個集合完全不動。
4. `(1, 0)`，`val = '6'`，`b = (1//3)*3 + 0//3 = 0`。無衝突 → 寫入。
   此時 `cols[0] = {'5','6'}`、`boxes[0] = {'5','3','6'}`。
5. `(2, 1)`，`val = '9'`，`b = (2//3)*3 + 1//3 = 0`。無衝突 → 寫入，`boxes[0] = {'5','3','6','9'}`。
6. `(2, 2)`，`val = '5'`，`b = 0`。檢查 `rows[2] = {'9'}` 沒有、`cols[2] = {}` 沒有，但 `'5'` 已經在 `boxes[0]` 裡 → **立刻回傳 `False`**。

注意第 6 步：這個 `'5'` 與第 1 步的 `'5'` 既不同列也不同行，只有宮格這條約束抓得到它。這正是宮格編號必須算對的原因。

## 程式碼實作

```python
class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        # 三種約束彼此獨立，所以各開一組長度 9 的 set 分開記錄，
        # 這樣一次掃描就能同時驗證，不必為每種約束各掃一遍盤面。
        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]

        for r in range(9):
            for c in range(9):
                val = board[r][c]

                # 題目只要求「已填入的數字」不衝突，空格不參與任何檢查，
                # 若不跳過，第二個 '.' 就會被誤判成重複。
                if val == '.':
                    continue

                # 乘 3 是為了讓 9 個宮格拿到互不相同的編號 0..8；
                # 少了這個 3，(0,1) 與 (1,0) 兩個不同宮格會撞成同一個 key。
                b = (r // 3) * 3 + c // 3

                if val in rows[r] or val in cols[c] or val in boxes[b]:
                    return False

                # 同一個數字要同時登記在三種約束上，缺一種就會漏判。
                rows[r].add(val)
                cols[c].add(val)
                boxes[b].add(val)

        return True
```

## 正確性說明

1. **不重複 (No Redundancy)**：每個格子只被讀取一次，`val` 至多被寫入三個集合各一次。集合的成員檢查與插入都是 $O(1)$，不存在重複掃描同一列或同一宮的行為。
2. **不遺漏 (Completeness)**：合法性由「列、行、宮格」三條約束構成，而任何一組重複必定發生在某兩個格子之間。掃描到這兩個格子中較晚的那一個時，較早的那個必然已經寫入對應集合，因此衝突一定會在該次檢查中被抓到——三個集合覆蓋了全部三種約束，沒有第四種情況。
3. **邊界條件**：
   - 全空盤面（81 個 `'.'`）：所有格子都被 `continue` 跳過，集合維持空的，回傳 `True`，符合題意。
   - 只填一格：無從衝突，回傳 `True`；題目不要求盤面有解，所以不需要額外判斷。
   - 衝突發生在最後一格：迴圈跑滿 81 次才回傳 `False`，仍然正確，只是沒有提早退出的紅利。
   - 同一數字跨宮格重複（例如 `(0,0)` 與 `(8,8)` 都是 `'5'`）：不同列、不同行、不同宮，三個集合都查不到 → 正確地判為合法。

## 複雜度分析

- **Time Complexity**: $O(N^2)$
  - 其中 $N = 9$ 為盤面邊長。外層與內層迴圈合計走訪 $N^2 = 81$ 個格子，每格做常數次集合查詢與插入。最壞情況（盤面合法或衝突落在最後一格）掃滿 81 格；最好情況是前兩格就撞號而提早回傳，僅 $O(1)$ 次操作。由於 $N$ 被題目固定為 9，實務上這是一個常數時間的解法。
- **Space Complexity**: $O(N^2)$
  - 共有 $3N = 27$ 個集合，每個集合至多存 $N = 9$ 個字元，總元素數上限為 $3N^2 = 243$，即 $O(N^2)$；同樣因 $N = 9$ 固定而等同常數空間。最好與最壞情況的空間開銷相同（集合一開始就配置好），且不需要複製盤面，輸入本身不被修改。

## 常見誤區

1. **宮格編號寫成 `r // 3 + c // 3`**：少乘一個 3，`(r//3, c//3)` 為 `(0,1)` 與 `(1,0)` 的兩個不同宮格會得到同一個編號 1，導致把不同宮的數字誤判為衝突（假陽性），同時也讓某些真正的衝突被稀釋。正確寫法是 `(r // 3) * 3 + c // 3`。
2. **忘記跳過 `'.'`**：若把 `'.'` 也加進集合，掃到該列的第二個空格時就會查到「已存在」而回傳 `False`。幾乎所有真實盤面都有多個空格，這個錯誤會讓答案幾乎恆為 `False`。
3. **三種約束共用同一個 `set`**：例如只開一個 `seen` 集合把所有數字丟進去，等於在檢查「整個盤面 81 格不重複」，但數獨本來就會有 9 個 `'1'`。正確做法是三組、每組 9 個獨立集合；若想用單一集合，必須把 key 編碼成 `('r', r, val)`、`('c', c, val)`、`('b', b, val)` 這種帶維度標籤的形式。
4. **誤以為要判斷盤面「有解」**：本題只驗證當前已填數字是否互相衝突，不需要回溯求解。想順手做完整求解會超時，也答錯題意——那是 LeetCode 37。
5. **拿字串去和整數比較**：`board[r][c]` 是 `'5'` 而非 `5`，寫成 `if board[r][c] == 0` 或 `int(val)` 之後才存進集合都可能出錯（後者遇到 `'.'` 會直接拋 `ValueError`）。整題從頭到尾用字串處理最省事。

## 小結

這題屬於**雜湊集合的多重約束驗證**題型：辨認出幾組互相獨立的約束，替每一組開一份狀態，然後用單次掃描同時維護。

**核心觀念：**

- 獨立的約束可以在同一次掃描中平行檢查，不需要為每種約束各跑一輪迴圈。
- 二維座標壓成一維索引的標準做法是 `(r // k) * k + c // k`，這個公式在矩陣分塊題型反覆出現，務必記牢乘法那一步。
- 集合帶來的是 $O(1)$ 的「看過沒有」查詢，把原本要掃 27 格的比對降成一次查表。
